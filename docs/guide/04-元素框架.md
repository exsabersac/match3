# 04 元素框架

> 本章讲规则层怎么做到「新元素只写几个 instance、在类型列表里加一项，主流程不用改」，以及加一个元素实际要碰哪些文件。
> 能力表、规则顺序表、扩展钩子的完整清单在 [architecture.md「元素框架与事件」](../architecture.md#元素框架与事件)；
> 元素类的写法演变见 [haskell-features/02-类型类与抽象.md](../haskell-features/02-类型类与抽象.md) 与 [09-规则去重.md](../haskell-features/09-规则去重.md)，
> 本轮重构的设计稿与分刀记录见 [08 演进史](08-演进史.md)「元素类重构（第 0–6 刀）」。

## 1. 设计思路

框架模仿 xmonad 的 `LayoutClass` / `LayoutModifier` / `layoutHook`（对照表见 [architecture.md「与 xmonad LayoutClass 的对照」](../architecture.md#与-xmonad-layoutclass-的对照)）：

- **每种东西一个类型、几个 instance**，状态放在值里（例如 `newtype StoneE = StoneE Int`）。
- **能力是类方法**：引擎对「一格」的全部需求拆成六个能力小类，每个方法都带「普通宝石」的缺省，元素只覆盖自己不同的那几个；
  常见组合用 DerivingVia 原型包（`Obstacle` / `Fixed`）一次拿到。
- **规则是类型级方法**：「邻格真消除时这一格怎么变」「步末往哪蔓延」写成 `Kind` / `Layer` 的方法，由通用驱动统一执行；
  读整盘、按自己顺序写回的规则走逃生口 `boardPasses` / `layerPasses`。
- **主流程只问世界（`World`）**：「这一格能不能交换？被炸到怎么反应？会不会下落？」都是 `…With :: World -> …` 查询，不点名任何具体元素。
- **关卡级机制的节拍是有类型的方法**（`Mechanic`），缺省 = 不回复。

演变：第二刀 2b（`51b1cfa`）先做了扁平记录 `ElementDef` + 注册表；元素类原型 `9ae6a7b` → 迁移 `b30cecd` → 按功能分文件 `2121bf8`；
段 4（`7630d8b`）把主流程里残留的专门分支收进框架；第 9 刀（`ac211d8`）把能力拆成能力记录 `Caps`；可扩展性 P2（`b5deb86`）加显示能力。
2026-10 的**元素类重构**（第 0 刀 `458832d` … 第 6 刀）把能力记录、修饰器类、注册表、开放消息全部换成本章描述的类型类写法，
金标准 `golden.txt`、元素查询快照 `element-queries.txt` 与元素对照快照 `element-oracle.txt` 全程逐字节不变。

## 2. 四种「元素」

| 类别 | 类型类 | 存在包装 / 注册项 | 存在哪里 | 内置实例 |
|------|--------|-------------------|----------|----------|
| 本体（格子里的东西） | 能力六类 + `Kind`（`src/Match3/Element/Kind.hs`） | `SomeElement` / `kindDef @T` | 格子本身（`Cell`） | 22 个类型（`Builtin/{Gem,Obstacle,Collectible,Actor}.hs`；`SpecialGem` 一个类型覆盖四种特殊块） |
| 叠层（冰、草 / 藤 / 巧 …） | `Layer`（`src/Match3/Element/Layer.hs`） | `Layered l e` / `layerDef @L` | 宝石格的冰层 / 叠层字段 | 9 个（`Builtin/Layer.hs`：冰 + 草、藤、巧克力、迷雾、锁链、冰冻、窗帘、蒸汽） |
| 地面层（果冻、魔法地格） | `GroundKind`（`Kind.hs`） | `groundDef @G` | 关卡级的地面层状态（不占格） | 2 个（`Builtin/Ground.hs`） |
| 关卡级机制（不在格子里） | `Mechanic`（`src/Match3/Element/Mechanic.hs`） | `SomeMechanic` / `registerMechanic` | `GameState.gsLevelElems` | 7 个可注册（`Builtin/Level.hs`：飞碟、皮带、传送门、地毯、L/T 炸弹开关、魔力鸟组合开关、饼干掉落口）+ 核心机制地面层 `GroundLayer` |

另有惰性占格 `Inert`（`inertDef "名字"`）：挡交换、不点火、会下落、打不动；世界里没人认领的格子也解码成它。

### 2.1 值级能力：六个小类（`src/Match3/Element/Ability.hs`）

| 类 | 方法（缺省 = 普通宝石） | 用途 |
|----|------------------------|------|
| `Cellular` | `nameOf`、`toCell`（`Int` newtype 元素缺省写成 `Custom 名字 (CustomState n)`） | 名字与写回存储 |
| `Matchable` | `color`、`blocksMatch`、`blocksSwap`、`hintable` | 颜色、挡匹配、挡交换、进不进普通提示 |
| `Hittable` | `struck :: e -> Strike`（`Absorb Cell` / `Destroy` / `Immune`）、`fires`、`blast` | 直接命中的反应、能否点火、爆炸范围 |
| `Movable` | `falls`、`portal`、`drains`、`keepOnShuffle`、`recolorable`、`pushable` | 下落、传送门、边缘收集、洗牌保留、被改色 / 推动 |
| `Countable` | `counter`、`diffWeight`、`vacatesCarpet` | 进入清除格的计数键、按差计数的权重、离格覆盖地毯 |
| `Renders` | `face`（附加显示字段）、`faceBase`（前端格子的类型标签与基本字段，第 6 刀） | 前端显示 |

`Element` 是把六个类捆在一起的**类同义词**（ConstraintKinds）；存在类型 `SomeElement` 只带这一个约束、逐类转发每个方法。
新增一个能力方法要动四处：类里加方法与缺省、`SomeElement` 转发一行、`Layered` 合成一行、`abilityProbe` 加一项——
`Spec.ElementAbility` 的 `ab_some_element_forwards_all_methods` / `ab_layered_composes_all_methods` 按源码核对，漏一处就失败。

原型包（DerivingVia）：`Obstacle`（挡交换、不点火、打不动、洗牌保留、不过门、不被改色 / 推动，会下落）与 `Fixed`（同障碍，另外不下落）。

一个完整的内置元素（`src/Match3/Element/Builtin/Obstacle.hs` 的石头）：

```haskell
newtype StoneE = StoneE Int
  deriving (Eq, Show)
  deriving (Matchable, Movable) via (Obstacle StoneE)

instance Cellular StoneE where
  nameOf _ = "stone"
  toCell (StoneE n) = Stone n

instance Hittable StoneE where
  struck (StoneE n) = chip n Stone          -- 削一层，末层 Destroy
  fires _ = False

instance Countable StoneE where
  counter _ = Just CountStones

instance Renders StoneE where
  faceBase (StoneE k) = Just ("stone", [nField k])

instance Kind StoneE where
  kindName _ = "stone"
  fromCell cell = case cell of
    Stone n -> Just (StoneE n)
    _ -> Nothing
  place _ = layersPlace Stone
  neighbourPrio _ = Just 10                 -- 邻格规则的顺序号
  onNeighbourClear (StoneE n) = chipNudge n Stone
```

`Custom` 元素更短（毛球，`Builtin/Actor.hs`）：`toCell` 用缺省，`fromCell = fromCustom "fuzzball" Fuzzball`，
`place _ = customPlace "fuzzball"`，`label _ = Just "毛球"`，规则走逃生口 `boardPasses _ = [AdjacentPass 190 …, EndPass (moveRule 20 …)]`。

### 2.2 类型级：`Kind` / `Entity` / `GroundKind`（`src/Match3/Element/Kind.hs`）

`Kind` 的方法都带 `proxy e` 参数（只有 `fromCell` 和 `onNeighbourClear` 吃值），不需要「原型值」：

| 方法 | 含义 |
|------|------|
| `kindName`、`fromCell :: Cell -> Maybe e` | 名字（与 `nameOf` 相同，测试钉住）、从存储解码 |
| `place`、`label`、`loseHint` | 关卡放置、目标中文名、失败提示 |
| `diffCounter`、`bonusMoves` | 按差计数的键、开局送步数 |
| `neighbourPrio`、`reach`（`SkipDirect` / `AllNeighbours`）、`onNeighbourClear :: e -> Nudge` | 邻格规则：顺序号、跳不跳过本轮直接命中的格、这一格怎么变（`Untouched` / `Becomes Cell` / `Dies`） |
| `boardPasses :: proxy e -> [BoardPass]` | 逃生口：`AdjacentPass` / `EndPass` / `SwapPass` / `OpenPass` |

多格实体（雪怪 Boss）另写 `Entity`：`footprint` / `partNo` / `hitPoints` / `withHp`，扣血由通用驱动 `entityDamage` 算。
地面层 `GroundKind` 是**不带值的类型**：`groundName` / `groundHit` / `groundCounter` / `groundWiden`（魔法地格扩爆）/ `groundLabel` / `groundLoseHint`。

### 2.3 叠层：`Layer` 与 `Layered`（`src/Match3/Element/Layer.hs`）

叠层只覆盖要改的方法：`peel :: Cell -> Maybe (l, Cell)`（从格子剥下本层）/ `putOn`（盖回去）、`layerBlocksMatch` / `layerBlocksSwap`、
`layerFires :: l -> Maybe Bool`、`layerHit :: l -> LayerHit l`（`Pierce` 问里面 / `Keep l'` 换层 / `Peel` 揭掉 / `Shatter` 连本格一起碎）、
`layerStripsOnClear`、`layerPlace`，规则方法 `layerNeighbourPrio` / `layerReach` / `onLayerNeighbourClear` / `spreads`（步末蔓延），逃生口 `layerPasses`。

冰层（`Builtin/Layer.hs`）：

```haskell
instance Layer Ice where
  layerName _ = "ice"
  peel cell = case cell of
    Gem c k n ov | n > 0 -> Just (Ice n, Gem c k 0 ov)
    _ -> Nothing
  putOn (Ice n) cell = case cell of
    Gem c k _ ov -> Gem c k n ov
    _ -> cell
  layerFires (Ice n) = Just (n <= 1)
  layerHit (Ice n)
    | n > 1 = Keep (Ice (n - 1))   -- 多层冰只削一层
    | otherwise = Shatter          -- 末层冰随宝石一起碎
```

通用包装 `Layered l e` 把叠层和里面的元素合成一个元素，合成规则**只在 `Layered` 的各 instance 里写一次**：
挡匹配 / 挡交换 = 本层 OR 里层；点火本层有意见（`Just`）就听本层；命中本层先回答，穿透时问里层、里层吃掉命中就把本层盖回去；
洗牌保留有任何一层就保留；名字、颜色、下落、计数、显示取里层。

### 2.4 世界：解码与查询（`src/Match3/Element/World.hs`）

注册的只是一张**有序的类型列表**（`src/Match3/Element/Builtin.hs` 的 `builtinDefs`，36 项）：

```haskell
builtinDefs =
  [ kindDef @PlainGem
  , kindDef @(SpecialGem 'LineH)
  …
  , layerDef @Ice
  …
  , groundDef @Jelly
  …
  ]

defaultWorld =
  setShapeRules builtinShapeRules . setComboRules builtinComboRules $
    foldl (flip registerMechanic) (mkWorld builtinDefs) builtinMechanics
```

- **解码**：`elementOf w cell` 先按注册的叠层由外向内 `peel`（冰在外、叠层在内，由 `Cell` 编码决定），剩下的交给本体的 `fromCell`，
  都不认识时得到 `Inert`；结果是 `Layered … (SomeElement body)`。按 `cellSlot` / 叠层编号 / `Custom` 名字建的候选缓存在建世界时算好（注册倒序：同名以后注册的为准）。
- **查询**：主流程的 `…With :: World -> …`（`matchColorWith`、`blocksSwapWith`、`directHitWith`、`fallsWith`、`counterWith`、`blastWith`……）
  就是在解码出的元素值上调能力方法；显示查询 `faceFieldsWith` / `displayLabelWith` / `loseHintWith`，前端格子描述 `Match3.View.cellFaceWith`。
- **建世界的检查**：`mkWorldChecked` 报 `DuplicateName` / `SharedCell` / `Unclaimed`（`Spec.ElementClass` 覆盖）。
- **规则表**：特殊块形状表 `shapeRules`、组合表 `comboRules`、补子策略 `refillPolicyWith`（各有 `set…`）。
- **本步上下文** `StepCtx`（`wStep` 字段，`noStep` 为空）：只在一步结算期间有意义的数据，目前是魔法地格的扩爆格（`setWidening` / `widenedCells`）。
  放在 World 里而不是另穿一个参数，所以 Clear / Cascade / Trace 不用改签名。
- 测试 / 扩展：`register (kindDef @Thorn) defaultWorld`、`registerMechanic` / `removeMechanic`，再走 `…With` 入口或 `match3GameWith w`。

### 2.5 规则：方法 + 通用驱动 + 逃生口（`src/Match3/Element/Rules.hs`）

`kindRules` / `layerRules` 在建世界时把方法给出的规则和逃生口收集一次、按顺序号排好：

- **邻格规则**（`kindNeighbour` / `layerNeighbour`）：按真消除格的顺序、每格上下左右，找界内、认得出这种元素 / 叠层的格，整体去重；
  `SkipDirect` 去掉本轮直接命中的格；`Dies` 用 `nub (q : dead)` 前插。内置顺序：石头 10 → 宝箱 20 → … → 雪怪 200（完整表在 `Builtin.hs` 头注释）。
- **蔓延**（`layerSpread`）：来源取步首盘面，落点是正交相邻的裸宝石。
- **多格实体**（`entityDamage`）：伤害 = 身外一圈的真消除格数 + 部件上的直接命中格数。
- **逃生口**：读整盘、按自己的顺序写回的规则（步末 `EndRule`、成对交换 `SwapRule`、开启 `OpenRule`、同色邻消 / 改色等）照旧写成函数，
  挂在 `boardPasses` / `layerPasses` 上。步末规则的阶段与顺序见 [03 §2.5](03-一步棋的生命周期.md#25-步末阶段)。

驱动的顺序语义与第 3 刀之前的手写函数逐项相同，由元素对照快照（`AR` / `ER` 行）与金标准锁定；`ab_rule_methods_pinned` 钉住每种内置元素的方法值。

### 2.6 关卡级机制：`Mechanic` 的节拍

```haskell
class (Typeable m, Eq m, Show m) => Mechanic m where
  mechName  :: m -> ElementName
  mechStart :: Level -> m -> m      -- 从关卡记录取开局状态
  mechCore  :: m -> Bool            -- 核心机制（地面层）不用注册、总参与
  -- 以下节拍缺省都是 Nothing（不回复）
```

主流程在流水线的固定节拍上调 `Match3.Element.Level` 的折叠：`beatIn`（带状态：按注册顺序折叠所有回复者，前一个的回复是后一个的输入，
推进后的状态写回 `gsLevelElems`）与 `queryIn`（状态不变）。

| 方法 | 节拍（谁调） | 内置回复者 |
|------|-------------|-----------|
| `shapes` | 每步结算开始换特殊块形状表（`levelWorldIn`） | L/T 炸弹开关 `BombShapes`（第 41 关） |
| `morph` | 交换成立前（`morphIn`；第一个回复者为准） | 魔力鸟组合开关 `RainbowCombos`（第 44 关） |
| `onSettling` | 每次沉降之后（钩子 `onSettle`） | 传送门 `PortalLevel` |
| `refillPolicy` | 补子前换补子策略（钩子 `hookRefill`） | 掉落口 `CookieDrop`（第 46、47 关） |
| `onRefilled` | 补子之后的整轮吸收（钩子 `onAbsorb`） | 飞碟 `UfoLevel` |
| `onEndTick` / `avoidCells` | 步末皮带 / 移动阶段（`beltShiftIn` / `avoidCellsIn`） | 皮带 `BeltLevel` |
| `wallCells` | 步末移动阶段（`wallCellsIn`） | 传送门 `PortalLevel` |
| `onGroundHit` | 结算汇总（`hitGroundIn`） | 地面层 `GroundLayer`（核心机制，定义在 Mechanic 模块） |
| `onCover` | 结算汇总（`coverIn`） | 地毯 `CarpetLevel` |
| `judge` | 胜负判定后（`judgeIn`） | 无（扩展用；测试 `judge_default_no_replier`） |

读数 `ufos` / `belts` / `portals` / `carpetOpen` / `ground` / `drops` 返回 `Maybe`（`Nothing` = 不提供，读的一方取第一个提供的），供前端与 GameState 的派生字段使用。
钩子记录 `LevelHooks`（`src/Match3/Board/Hooks.hs`）是 Board 层看到的唯一接口：Board 层只调钩子，不知道背后是哪种机制。
需要**新节拍**的机制要在 `Mechanic` 加方法（带 `Nothing` 缺省）并在主流程的对应位置调一次 `beatIn` / `queryIn`。

## 5. 框架的边界（还做不到的）

摘自 [architecture.md「专门分支的收编」的「遗留」](../architecture.md#专门分支的收编段-4) 与可扩展性审核：

- 需要**新节拍**的关卡级机制（节拍由主流程在固定位置调用）仍要改主流程，并在 `Mechanic` 加一个带缺省的方法。
- `Custom` 只能存一个 `Int`；`boardSeed = fnv . show` 把 `Show Cell` 的文本钉成了行为的一部分（毛球 / 雪怪按盘面散列选格），所以 `Cell` 的表示实际上改不动。
- 内置元素的早期构造器（`Stone` … `Countdown`）仍在 `CellContents` 里，没有统一成 `Custom`；宝石格（含冰层 / 叠层）的前端描述仍由 View 按存储编码给出。
- 逃生口里的规则（步末 / 成对交换 / 开启 / 同色邻消等）仍是读整盘的函数，只有邻格与蔓延两类规则完全方法化。
- `Game.State` 的若干设置器（`setUfos` 等）与 `builtinLevel` 的 Show 过滤仍点名内置机制类型。
- 前端每个有专门画法的元素要写三份（桌面贴图、桌面几何、网页 JS）；审计第 12 项（合并 `*Prim` / `*Art`）按建议没做（`docs/backlog.md` §4）。
