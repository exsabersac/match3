# 04 元素框架

> 本章讲规则层怎么做到「新元素只写一个原型值、在注册表里加一项，主流程不用改」，以及加一个元素实际要碰哪些文件。
> 2026-10 的 **ECS 重写**（分支 `feat/ecs`，ecs-1…ecs-7）之后，元素不再是类型类的 instance，而是 **ECS 范式**：
> 格子 = 实体，元素 = 带纯数据组件的**原型**，逻辑全部在按显式顺序组成流水线的 **system**（`w -> w` 纯函数）里。
> 能力表、规则顺序表、扩展钩子的完整清单在 [architecture.md「元素框架与事件」](../architecture.md#元素框架与事件)；
> 类型类写法（Phase / Layer / Mechanic）的来龙去脉见 [08 演进史](08-演进史.md)「元素类重构」「接口收缩」「ECS 重写」三节，
> 设计稿在仓库外的 `/workspace/match3-ecs-design.md`。

## 1. 设计思路

| ECS 概念 | 在本仓库里是什么 | 模块 |
|----------|------------------|------|
| 实体 | 盘面上的格（`Pos`）；关卡级机制是不在格子里的单例实体 | — |
| 组件存储 | `Cell`（一行**打包的组件**，编码不变：`boardSeed = fnv . show` 与三份快照依赖它的派生 `Show`） | `Match3.Types` |
| 组件 | 纯数据记录：`Match`、`OnHit`、`Physics`、`Tally`、`Face`、`Hud`、`DiffCount`，叠层的 `Shield`，地面层的 `Wear` / `Widen`，机制的 `LevelView` | `Match3.ECS.Component`、`ECS.Cover`、`Element.Mechanic` |
| 原型（archetype） | 一种元素 = 一个**值**：存储列 + 「状态 → 组件」的派生 + 自带的 system 列表 | `ECS.Archetype`（本体）、`ECS.Cover`（叠层）、`Element.Kind`（地面层 `GroundArch`）、`Element.Mechanic`（机制） |
| system | `newtype System w = System (w -> w)`；`a <> b` = 先 a 后 b，`pipeline = mconcat` | `Match3.ECS.System` |
| 阶段世界 | 每个结算阶段一个世界类型 = 整盘 + 本阶段黑板：`NearWorld`（邻格）、`EndWorld`（步末）、`OpenWorld`（开启）、`WaveWorld`（一轮消除）、`StepWorld`（步尾） | `ECS.Stage`、`Board.Clear`、`Game.Resolve` |
| 调度表 | 元素声明的 system 带阶段与次序（`SysDef`），注册表建世界时收集一次、按次序稳定排序（`Scheduled` / `schedule`） | `ECS.System`、`ECS.Registry` |
| 注册表 | `Registry`：解码（格 → 一行组件）+ 按组件查询（`…With :: Registry -> …`）+ 调度表 + 规则表 + 机制原型表 | `Match3.ECS.Registry` |

要点：

- **组件是数据，不是方法**。「这格挡不挡交换」= 读 `Match` 组件的 `mBlockSwap`；「被炸到怎么样」= 读 `OnHit`（`hStrike`：吸收一层 / 消除 / 免疫，`hFires`、`hBlast`）。
  原型字段 `aMatch :: s -> Match` 之类是**状态到组件的派生**（石头的层数决定它的 `Face`），不是行为钩子。
- **行为都在 system 里，顺序是显式的**。邻格反应（石头削层、气球打破、魔法帽换色、雪怪扣血）、步末行动（倒计时、蔓延、蜗牛、毛球、变色龙）、
  成对交换、开启，都是元素带来的 system，注册表按（阶段, 次序）排好；一轮消除与步尾本身也是写死顺序的 system 流水线（`waveSystems` / `stepSystems`）。
- **特殊元素有自己的 system**，不在通用记录里塞开关：雪怪的扣血是 `SysNear 200 (entityDamage …)`，魔法石的发射是 `tickSys 20 …`。
- **不是「纯数据配置化」**：组件是有类型的 Haskell 记录，system 是纯函数，原型是普通值（可以用记录更新从另一个原型派生）；
  只有极少数地方组件里放函数（见 §5「组件里仍有函数的地方」）。
- **主流程只问注册表**：「这一格能不能交换？被炸到怎么反应？会不会下落？」都是 `…With :: Registry -> …` 查询，不点名任何具体元素。

## 2. 四种「元素」

| 类别 | 原型 | 装箱 / 注册项 | 存在哪里 | 内置 |
|------|------|---------------|----------|------|
| 本体（格子里的东西） | `Archetype s`（`src/Match3/ECS/Archetype.hs`） | `SomeArchetype` / `kindDef stoneArch` | 格子本身（`Cell`） | 25 个原型值（`Builtin/{Gem,Obstacle,Collectible,Actor}.hs`；四种特殊块各一个原型） |
| 叠层（冰、草 / 藤 / 巧 …） | `Cover l`（`src/Match3/ECS/Cover.hs`） | `SomeCover` / `coverDef iceCover` | 宝石格的冰层 / 叠层字段 | 9 个（`Builtin/Layer.hs`：冰 + 草、藤、巧克力、迷雾、锁链、冰冻、窗帘、蒸汽） |
| 地面层（果冻、魔法地格） | `GroundArch` **全数据记录**（`Element/Kind.hs`） | `groundDef jelly` | 关卡级的地面层状态（不占格） | 2 个值（`Builtin/Ground.hs`：`jelly`、`magicGround`） |
| 关卡级机制（不在格子里） | `Mechanic m` 记录（`src/Match3/Element/Mechanic.hs`） | `SomeMechanic (Mechanic m) m` / `registerMechanic` | `GameState.gsLevelElems` | 7 个可注册（`Builtin/Level.hs`：飞碟、皮带、传送门、地毯、L/T 炸弹开关、魔力鸟组合开关、饼干掉落口）+ 核心机制地面层 |

另有惰性占格 `inertArch`（`inertDef "名字"`）：挡交换、不点火、会下落、打不动；注册表里没人认领的格子也解码成它。
注册项 `Def = KindDef SomeArchetype | LayerDef SomeCover | GroundDef GroundArch | InertDef`，内置表 `builtinDefs` 共 36 项。

### 2.1 本体：`Archetype s`（`src/Match3/ECS/Archetype.hs`）

```haskell
data Column s = Column { colGet :: Cell -> Maybe s, colPut :: s -> Cell }   -- 存储列：这行是不是我的、状态怎么写回

data Archetype s = Archetype
  { aName    :: ElementName      -- 元素名（注册表的键）
  , aColumn  :: Column s         -- 存储列
  , aSpawn   :: Placer           -- 关卡放置（参数解析，属于存储层）
  , aMatch   :: s -> Match       -- 组件派生：颜色、挡匹配、挡交换、进不进普通提示
  , aHit     :: s -> OnHit       --           直接命中：Absorb / Destroy / Immune、点火、爆炸范围
  , aPhysics :: s -> Physics     --           固定、下落、穿门、可改色、可推动、洗牌保留、边缘收集
  , aTally   :: s -> Tally       --           计数键、按差权重、离格覆盖地毯
  , aFace    :: s -> Face        --           前端格子描述（fBase / fExtras）
  , aDiff    :: Maybe DiffCount  -- 原型级：按个数差计数（保险箱、时间精灵 +2 步）
  , aHud     :: Hud              -- 原型级 HUD：目标中文名、失败提示、图标、血条
  , aSystems :: [SysDef]         -- 本元素带来的 system
  }

data SysDef = SysNear Int (System NearWorld) | SysEnd EndSys | SysSwap SwapSys | SysOpen (System OpenWorld)
```

缺省原型 `archetype "名字" 列`（惰性占格的组件），元素用记录更新改掉自己不同的部分。列的构造子：`prismColumn _Stone`（棱镜）、
`customColumn` / `intColumn`（`Custom 名字 n`）、`unitColumn`（无状态）。石头、宝箱、蜂蜜、蛋糕共用一个原型构造函数
（`src/Match3/Element/Builtin/Obstacle.hs`）：

```haskell
durable :: ElementName -> Prism' Cell Int -> (Int -> Cell) -> CounterKey -> Int -> Archetype Int
durable n p con key order = (archetype n col)
  { aSpawn = layersPlace con
  , aHit = chipHit col                                  -- 削一层，末层 Destroy，不点火
  , aTally = const emptyTally {tCounter = Just key}
  , aFace = \k -> baseFace (unElementName n) [nField k]
  , aSystems = [SysNear order (chipNear col)]           -- 邻格真消除时削一层（邻格 system，次序 = order）
  }

stoneArch = durable "stone" _Stone Stone CountStones 10
```

解码出的一行是 `Row = forall s. Row (Archetype s) s`；按组件类型查询 `rowGet @Match row`、`rowGet @Physics row`（`Component` 类只做存储索引），
`rowProbe` 读出一行的全部组件（`ab_row_probe_reads_all_components` 要求每个 `Component` 实例都在里面）。
多格实体（雪怪 Boss）的 `Entity` 是普通记录（`footprint` / `partNo` / `hitPoints` / `withHp`），扣血 system 由通用的
`Match3.Element.Rules.entityDamage 列 记录` 生成、挂在原型的 `aSystems`（护栏 `ec_entity_wires_damage`）。

### 2.2 叠层：`Cover l`（`src/Match3/ECS/Cover.hs`）

```haskell
data CoverColumn l = CoverColumn { ccPeel :: Cell -> Maybe (l, Cell), ccPut :: l -> Cell -> Cell }   -- 剥下 / 盖回（定律：ab_cover_column_law）

data Shield l = Shield                 -- 纯数据组件，由本层状态算出
  { sBlocksMatch, sBlocksSwap :: Bool
  , sFires   :: Maybe Bool             -- Just = 本层决定点不点火
  , sHit     :: LayerHit l             -- Pierce 问里面 / Keep l' 换层 / Peel 揭掉 / Shatter 连本格一起碎
  , sStrips  :: Bool }                 -- 真消除时随格清掉

data Cover l = Cover { cvName, cvColumn, cvSpawn, cvShield :: l -> Shield l, cvSystems :: [SysDef] }
```

冰层（`Builtin/Layer.hs`）：

```haskell
iceCover :: Cover Int
iceCover = (mkCover "ice" iceColumn)
  { cvShield = \n -> openShield {sFires = Just (n <= 1), sHit = if n > 1 then Keep (n - 1) else Shatter}
  , cvSpawn = …                                                         -- 设冰层数
  }
```

合成规则（本层先回答，没意见再问里层）**只在注册表的 `wholeMatch` / `wholeHit` / `wholePhysics` 里写一次**：
挡匹配 / 挡交换 = 本层 OR 里层；点火本层有意见就听本层；命中本层先回答，穿透时问里层、里层吃掉命中就把本层盖回去；
洗牌保留有任何一层就保留；名字、颜色、下落、计数、显示取里层。解码出的一层是 `Peeled = forall l. Peeled (Cover l) l`。
叠层的邻格揭层 / 清掉（`coverNear`）与步末蔓延（`coverSpread`）也是 `cvSystems` 里的普通 system。

### 2.3 地面层：`GroundArch`（`src/Match3/Element/Kind.hs`）

```haskell
data GroundArch = GroundArch
  { groundName    :: ElementName
  , groundWear    :: Wear               -- Durable（被消除不变）| WearsOut（每次去一层），由 wearHit 解释
  , groundCounter :: Maybe CounterKey   -- 去层计数
  , groundWiden   :: Maybe Widen        -- WidenRing：本格上的特效引爆时范围扩一圈（由 widenArea 解释）
  , groundHud     :: Hud }
```

全是数据：`jelly = (groundArch "jelly") {groundWear = WearsOut, groundCounter = Just (CountNamed "jelly"), …}`，
`magicGround = (groundArch magicGroundName) {groundWiden = Just WidenRing}`（名字 `"magic"`）。由核心机制地面层在 `OnGroundHit` 节拍上消费。

### 2.4 注册表：解码与查询（`src/Match3/ECS/Registry.hs`）

注册的是一张**有序的原型列表**（`src/Match3/Element/Builtin.hs` 的 `builtinDefs`，36 项）：

```haskell
builtinDefs =
  [ kindDef gemArch
  , kindDef lineHArch
  …
  , coverDef iceCover
  …
  , groundDef jelly
  …
  ]

defaultRegistry =
  setShapeRules builtinShapeRules . setComboRules builtinComboRules $
    foldl (flip registerMechanic) (mkRegistry builtinDefs) builtinMechanics
```

- **解码**：先按注册的叠层由外向内 `peelWith`（冰在外、叠层在内，由 `Cell` 编码决定），剩下的交给本体原型的 `colGet`，
  都不认识时得到惰性占格。按 `cellSlot` / 叠层编号 / `Custom` 名字建的候选缓存在建世界时算好（注册倒序：同名以后注册的为准）。
- **查询**：主流程的 `…With :: Registry -> …`（`matchColorWith`、`blocksSwapWith`、`directHitWith`、`fallsWith`、`counterWith`、`blastWith`……）
  就是在解码出的一行上读组件（有叠层时经 `whole*` 合成）；显示查询 `faceFieldsWith` / `displayLabelWith` / `loseHintWith`，前端格子描述 `Match3.View.cellFaceWith`。
- **调度表**：建世界时从各原型的 `aSystems` 与叠层的 `cvSystems` 收集 system，按（阶段, 次序）稳定排序；邻格 / 步末 / 交换 / 开启各一张。
- **建世界的检查**：`mkRegistryChecked` 报 `DuplicateName` / `SharedCell` / `Unclaimed`（`Spec.ElementClass` 覆盖）。
- **规则表**：特殊块形状表 `shapeRules`、组合表 `comboRules`、补子策略 `refillPolicyWith`（各有 `set…`）。
- **本步上下文** `StepCtx`（`noStep` 为空）：只在一步结算期间有意义的数据，目前是魔法地格的扩爆格（`setWidening` / `widenedCells`）。
- 测试 / 扩展：`register (kindDef thornArch) defaultRegistry`、`registerMechanic` / `removeMechanic`，再走 `…With` 入口或 `match3GameWith r`。

### 2.5 system 与阶段（`src/Match3/ECS/{System,Stage}.hs`、`Board/Clear.hs`、`Game/Resolve.hs`）

一步棋里的 system 流水线（顺序都写在代码里，书写顺序 = 执行顺序）：

| 阶段 | 世界 | system（顺序） |
|------|------|----------------|
| 一轮消除 | `WaveWorld` | `waveSystems`：展开爆炸 → 直接命中按层结算 → 开启（彩蛋） → 剥随格叠层 → **邻格**（下一行） → 挖空 → 生成特殊块 |
| 邻格 | `NearWorld` | 调度表：石头 10 → 宝箱 20 → 蜂蜜 30 → 蛋糕 40 → 气球 50 → 魔法帽 60 → 迷雾 70 → 锁链 80 → 冰冻 90 → 窗帘 100 → 保险箱 110 → 时间精灵 120 → 果汁机 130 → 染色瓶 140 → 巧克力 150 → 蒸汽 160 → 气泡 170 → 魔法石 180 → 毛球 190 → 雪怪 200 |
| 步末（交换后） | `EndWorld` | `PhaseTick`：倒计时 10 → 魔法石 20；皮带（关卡级 `OnEndTick`）；`PhaseSpread`：藤 10 → 巧 20 → 蒸汽 30；`PhaseMove`：蜗牛 10 → 毛球 20 → 雪怪 30 → 变色龙 40（道具之后只有 `PhaseSpread`） |
| 成对交换 | `SwapSys` | 彩虹取色 10 → 彩虹 × 变色龙 15 → 特殊合成 20（组合表并成的一条） |
| 开启 | `OpenWorld` | 彩蛋 |
| 步尾 | `StepWorld` | `stepSystems`：地面层 → 地毯 → 前后差计数 → 计数汇总 → 提交（盘面 / 分数 / 步数） → 胜负 → 自动洗牌 |

阶段世界的约定：邻格 system 看到的产出字段（`nwDead` / `nwSit`）是空的，跑完由 `runNearStage` 按顺序并入总账；步末 system 看到的 `ewEffect` 是 `Nothing`，
跑完有效果就记一条（前盘, 后盘, 效果）进回放脚本；`WaveWorld` / `StepWorld` 的每个黑板字段只由一个 system 写入（字段注释写明写入者，`br_wave_and_step_stage_systems` 锁定）。

### 2.6 关卡级机制：`Mechanic m` 与节拍 system

```haskell
data Mechanic m = Mechanic
  { mechName    :: ElementName
  , mechCore    :: Bool                -- 核心机制（地面层）不能 removeMechanic
  , mechView    :: m -> LevelView      -- 读数组件：飞碟 / 皮带 / 传送门 / 地毯 / 地面层 / 掉落口（前端与查询用）
  , mechSystems :: [MechSys m] }       -- 按节拍的 system

data SomeMechanic = forall m. (Typeable m, Eq m, Show m) => SomeMechanic (Mechanic m) m
```

飞碟（`Builtin/Level.hs`）：

```haskell
ufoMech = (mechanic "ufo")
  { mechView = \(UfoLevel us) -> noView {lvUfos = Just us}
  , mechSystems =
      [ OnStart $ \lvl _ -> …                                     -- 开局按关卡记录给出飞碟
      , OnRefilled $ \b acc (UfoLevel us) -> let (ps, us') = stepUfos b us in Just (acc ++ ps, UfoLevel us') ] }
```

主流程在流水线的固定节拍上调 `Match3.Element.Level` 的折叠：`beatIn`（推进型：按参与顺序折叠所有回复者，前一个的回复是后一个的输入，
推进后的状态写回 `gsLevelElems`）与 `queryIn`（问答型：状态不变）；参数是选择器（`onRefilled b`、`onEndTick`、`askAvoid` …）。

| `MechSys` 构造子 | 节拍（谁调） | 内置参与者 |
|------------------|-------------|-----------|
| `OnStart` | 开局（`startLevelsWith`，按关卡记录给出初始状态） | 全部内置机制 |
| `AnswerShapes` | 每步结算开始换特殊块形状表（`levelRegistryIn`） | L/T 炸弹开关（第 41 关） |
| `AnswerMorph` | 交换成立前（`morphIn`；第一个回复者为准） | 魔力鸟组合开关（第 44 关） |
| `OnSettling` | 每次沉降之后（钩子 `onSettle`） | 传送门 |
| `AnswerRefill` | 补子前换补子策略（钩子 `hookRefill`） | 掉落口（第 46、47 关） |
| `OnRefilled` | 补子之后的整轮吸收（钩子 `onAbsorb`） | 飞碟 |
| `OnEndTick` / `AnswerAvoid` | 步末皮带 / 移动阶段（`beltShiftIn` / `avoidCellsIn`） | 皮带 |
| `AnswerWall` | 步末移动阶段（`wallCellsIn`） | 传送门 |
| `OnGroundHit` | 步尾 `groundStepSystem`（`hitGroundIn`） | 地面层（核心机制） |
| `OnCovering` | 步尾 `carpetStepSystem`（`coverIn`） | 地毯 |
| `AnswerJudge` | 步尾 `judgeStepSystem`（`judgeIn`） | 无（扩展用；测试 `judge_default_no_replier`） |

钩子记录 `LevelHooks`（`src/Match3/Board/Hooks.hs`）是 Board 层看到的唯一接口：Board 层只调钩子，不知道背后是哪种机制。
需要**新节拍**的机制要给 `MechSys` 加一个构造子，并在主流程的对应位置调一次 `beatIn` / `queryIn`。

### 4.1 规则层（`src/`）

| | 文件 | 改什么 |
|---|------|--------|

## 5. 框架的边界与取舍

摘自 [architecture.md「专门分支的收编」的「遗留」](../architecture.md#专门分支的收编段-4)、可扩展性审核与 ECS 重写的收尾记录：

- 需要**新节拍**的关卡级机制（节拍由主流程在固定位置调用）仍要改主流程，并给 `MechSys` 加一个构造子。
- `Custom` 只能存一个 `Int`；`boardSeed = fnv . show` 把 `Show Cell` 的文本钉成了行为的一部分（毛球 / 雪怪按盘面散列选格），所以 `Cell`（组件存储）的表示实际上改不动——
  ECS 重写也只换了「谁解释这行存储」，没有改存储本身。
- 内置元素的早期构造器（`Stone` … `Countdown`）仍在 `CellContents` 里，没有统一成 `Custom`；宝石格（含冰层 / 叠层）的前端描述仍由 View 按存储编码给出。
- `Game.State` 的若干设置器（`setUfos` 等）与 `builtinLevel` 的 Show 过滤仍点名内置机制。

**组件里仍有函数的地方**（有意保留，均为纯函数）：

| 位置 | 为什么是函数 |
|------|--------------|
| 原型的 `aMatch` / `aHit` / `aPhysics` / `aTally` / `aFace`、叠层的 `cvShield`、机制的 `mechView` | **状态 → 组件的派生**：组件随状态变（石头层数、冰层数、雪怪血量），存成函数等于「按需计算的组件」，结果本身是纯数据 |
| `aSystems` / `cvSystems` / `mechSystems` | 这就是 system 本身（ECS 里行为的归宿），挂在原型上只为让注册表能收集 |
| `aSpawn` / `cvSpawn`（`Placer`） | 关卡放置的参数解析，属于存储层（把 `Place "名字" [参数]` 写成一行） |
| `Column` / `CoverColumn` | 存储列的编解码（`Cell` 编码不变的代价） |
| `StepCtx` | 本步上下文（魔法地格的扩爆格）随注册表穿过一步，避免改 Clear / Cascade / Trace 的签名 |

**与类型类版本（slim-11）的取舍**：

- 得：组件可以直接比较、打印、在测试里逐项钉住（`rowProbe`）；新元素是一个值，可以由别的原型记录更新派生（`durable`），不用新类型 + instance；
  system 的执行顺序集中在调度表与 `waveSystems` / `stepSystems`，一眼能看全；`Phase` / `Layer` / `Mechanic` / `SpecialKind` 四个类与 GADT `Beat` 都删掉了。
- 失：元素状态类型不再由 instance 选择，`Row` / `Peeled` / `SomeMechanic` 都是存在类型，取回具体状态要 `fromMechanic` / `levelState`（`Typeable`）；
  阶段世界多了一层记录更新，三份快照生成器的分配量比 `main` 高 0.7%–1.7%（见 [08 演进史](08-演进史.md)「ECS 重写」）。
