# 09 术语表（中英对照）

> 玩法名词（各种宝石、障碍、叠层、地图机制）的规则说明见 [domain.md](../domain.md)；这里收的是**读代码、读文档时**常见的说法。
> 「代码名」一列是仓库里对应的类型、函数或字段，方便全文搜索。

## 1. 过程用语

| 中文 | 英文 / 代码名 | 含义 |
|------|---------------|------|
| 刀（第一刀、第 N 刀） | refactor cut | 一次单独推送、行为不变的重构。「三刀」在 2026-09-29，「11 刀」在 09-30（[08 §5、§7](08-演进史.md)） |
| 段（段 1–5） | — | 三刀之后补框架缺口的后续工作（推断，仓库未定义） |
| 新玩法 N | new mechanic N | 2026-09-30 新玩法清单的第 N 个实现，第 41–48 关 |
| 审计第 N 项 | audit item N | 10-03 代码审计报告的整改项（[backlog.md §4](../backlog.md#4-审计整改2026-10已完成)） |
| 可扩展性 P1 / P2 | extensibility P1/P2 | 10-04 可扩展性审核的整改，提交标题带「可扩展性 P2」 |
| 玩法冻结 | gameplay freeze | 2026-10-03 起不再加玩法、元素、关卡 |
| 快进合并 | fast-forward merge | 合 main 只推祖先校验过的完整 SHA（[testing.md「开发流程」](../testing.md#开发流程)） |
| 验收 | verify | `make verify` = `stack test` 全绿 |

## 2. 盘面与格子

| 中文 | 英文 / 代码名 | 含义 |
|------|---------------|------|
| 盘面 | board / `Board` | `type Board = Grid Cell`，二维不可变数组（`src/Match3/Types/Board.hs:128`） |
| 可变盘面 | `MBoard` | 结算过程中允许出现空洞的盘面 |
| 阶段标签 | stage tag / `Stage p` | 类型层标出盘面处于交换后、消除后、下落后、补满（[haskell-features/01](../haskell-features/01-类型层.md)） |
| 格子 | cell / `Cell` | 一格的内容：本体 + 冰层 + 叠层 |
| 本体 | body | 占格的那一层：宝石、特殊块、石头、饼干…… |
| 冰层 | ice / `SlotIce` | 挂在宝石上的层数，被消除时减一 |
| 叠层 | overlay / `SlotOverlay` | 挂在宝石上的草、藤蔓、巧克力、锁链等 |
| 地面层 | ground / `gsGround` | 格子下方的果冻、魔法地格 |
| 原型 | archetype / `Piece`·`Blocker`·`Fixed` | 本体的基本行为类别：棋子 / 占格障碍 / 固定格（`Match3.Element.Class`） |
| 宝石 | gem | 5 种颜色的普通棋子 |
| 特殊块 | special | 直线（横 / 竖）、炸弹、彩虹（魔力鸟） |
| 矩形盘面 | rectangular board | 5–10 行列；第 49 关 6×9，其余 8×8 |

## 3. 元素框架

| 中文 | 英文 / 代码名 | 含义 |
|------|---------------|------|
| 能力类 | ability classes / `Cellular`、`Matchable`、`Hittable`、`Movable`、`Countable`、`Renders` | 引擎对一格的全部需求拆成的六个小类，每个方法都带「普通宝石」缺省（`Match3.Element.Ability`） |
| 元素 | element / `Element` | 六个能力类（加 `Show` / `Eq` / `Typeable`）的类同义词 |
| 存在包装 | `SomeElement` / `SomeMechanic` | 把不同元素 / 机制装进同一个列表 / 字段 |
| 原型包 | archetype bundle / `Obstacle`、`Fixed` | DerivingVia 用的 newtype：一次拿到障碍 / 固定格的能力组合 |
| 本体种类 | kind / `Kind` 类 | 格子本体的类型级 API：解码 `fromCell`、放置、标签、邻格规则方法、逃生口 `boardPasses` |
| 多格实体 | entity / `Entity` 类 | 占多格的本体（雪怪）：`footprint` / `hitPoints` 等，扣血由通用驱动算 |
| 叠层 | layer / `Layer` 类、`Layered` | 冰层、叠层这类「套在本体外面」的东西；`Layered l e` 是叠层 + 里层合成的元素 |
| 地面层种类 | ground kind / `GroundKind` 类 | 不占格的地面层（果冻、魔法地格），不带值的类型 |
| 关卡级机制 | mechanic / `Mechanic` 类 | 不在格子里的机制：皮带、传送门、飞碟、地毯、规则开关、掉落口、地面层；状态在 `gsLevelElems` |
| 元素世界 | world / `World` | 有序的类型列表 + 解码缓存 + 排好序的规则；主流程经它的 `…With` 查询（`Match3.Element.World`） |
| 注册项 | def / `Def`、`kindDef @T` | 世界里的一项；内置 36 个（`builtinDefs`） |
| 惰性占格 | inert / `Inert` | 世界里没人认领的格子：挡交换、不点火、会下落、打不动 |
| 命中结果 | strike / `Strike` | `Absorb Cell`（吃掉命中、格子变样）/ `Destroy`（消除）/ `Immune`（打不动） |
| 邻格反应 | nudge / `Nudge` | 邻格真消除时这一格怎么变：`Untouched` / `Becomes Cell` / `Dies` |
| 逃生口 | escape hatch / `boardPasses`、`layerPasses` | 读整盘、按自己顺序写回的规则（步末 / 成对交换 / 开启 …） |
| 本步上下文 | step context / `StepCtx` | 只在一步结算期间有意义的数据（魔法地格扩爆格），World 的字段 |
| 节拍 | beat | 主流程在固定时机调关卡级机制的有类型方法：`onRefilled`、`shapes`、`onEndTick`、`onSettling`、`judge` 等（`Match3.Element.Mechanic`） |
| 规则开关 | rule toggle | 关卡级机制形式的规则：`bomb_shapes`、`rainbow_combos` |
| 自定义元素 | custom element / `Custom "名字"` | 新玩法常用的本体形式（魔法石、毛球、雪怪、变色龙） |

## 4. 一步棋的结算

| 中文 | 英文 / 代码名 | 含义 |
|------|---------------|------|
| 动作 | action / `Action` | `Swap` / `Hammer` / `FreeSwap` / `CrossClear` / `Hint` / `Shuffle`（`src/Match3/Engine.hs:57`）；撤销由外层 `Undoable` 的 `Undo` 表示 |
| 起手 | opening / `Opening` | 主连锁的起手方式：`OpenMatch`（普通匹配）/ `OpenSeeds`（种子起手）/ `OpenMorph`（先变身）（`src/Match3/Game/Resolve.hs:106`） |
| 交换校验 | swap validation | 相邻、双方可交换、能形成匹配（或特殊组合） |
| 匹配 | match / `MatchRun` | 横竖三连及以上 |
| 种子 | seeds | 本轮要消除的起始格（匹配格、爆炸范围、组合效果） |
| 真消除 | true clear | 格子本体真的被消掉（相对于只剥一层冰 / 叠层） |
| 直接命中 | direct hit | 消除 / 爆炸打到的格子按层结算：冰层 → 叠层 → 本体 |
| 邻格波及 | adjacent rule | 消除旁边的障碍被剥层（石头、蜂蜜、巧克力……），按 `arOrder` 顺序 |
| 点火 | activate | 特殊块被消时触发自己的爆炸范围 |
| 重力 | gravity | 本体下落、固定格把列分段 |
| 补子 | refill / `RefillPolicy` | 从顶部补新宝石的策略 |
| 连锁 | cascade | 补子后又形成匹配，继续下一轮 |
| 轮 / 波次 | wave / `CascadeWave` | 连锁的一轮：消除 → 下落 → 补子 |
| 连击 | combo | 一步内连锁的轮数，k ≥ 2 有弹字 |
| 步末 | end of move / `EndPhase` | 连锁停下后的非消除变化：tick（倒计时）→ belt（皮带）→ spread（蔓延）→ move（蜗牛等）→ settle → vacate |
| 胜负判定 | judging / `Judging` | 内置规则先判，再交关卡级元素复核 |
| 每步结果 | outcome / `Outcome` | `InvalidSwap` / `NoMatch` / `MoveApplied` / `Won` / `Lost` / `LevelClear`（`src/Match3/Types/Game.hs:30`） |
| 终局 | terminal / `Terminal` | `TWon` / `TLost` / `TLevelClear`，存在 `gsOver` |
| 目标 | goal / `Goal`、`Quota` | 计数键 + 目标值的列表 |
| 计数 | counts / `Counts`、`CounterKey` | 本关累计的各种数（消了多少色、收了多少饼干……） |
| 自动洗牌 | auto shuffle | 无可走步时重排，保留装饰 |

## 5. 回放、表现与前端

| 中文 | 英文 / 代码名 | 含义 |
|------|---------------|------|
| 回放脚本 | move trace / `MoveTrace` | 一步棋每一轮的盘面快照与步末记录 |
| 效果事件 | event / `Event`、`EventKind` | 规则层交给前端的「发生了什么」，11 种 |
| 边沿特效 | move effects / `MoveFx` | 本步的连击与清除格；为空表示不回放 |
| 阶段机 | stage machine / `Stages`、`Player` | 通用回放时钟（`Engine.Playback`），三消实例在 `ComboFx` |
| 步末段 | end stage / `EndStage` | 回放里的倒计时 / 皮带 / 蔓延 / 蜗牛 / 洗牌段 |
| 表现表 | presentation table / `presentationTable` | 事件种类 → 表现方式、帧数、颜色、碎屑、音效 |
| 视图模型 | view model / `Match3.View`、`GameView` | 前端只读的显示数据 |
| 通用接口 | game record / `Engine.Game` | 与游戏无关的「开局 / step / 结局」函数记录 |
| 外壳 | shell / `match3Shell` | 三消实例套上撤销历史（`withHistory`）后的通用接口实例；原 SDL 主循环 `Shell.Loop` 已随桌面版移除 |
| 插件 | plugin / `Plugin` | 历史名词：原 SDL 外壳 `Shell.Loop` 上三消的钩子集合（`UI.Plugin`），已随桌面版移除；网页的帧循环在 `web/www/main.js` |
| 撤销历史 | history / `Engine.History` | `withHistory` 给任意游戏加撤销 |
| 贴图 / 几何降级 | art / primitive fallback | 有贴图画贴图，缺贴图逐格退回纯色块 + 元素缩写（网页 `cells.js` 的 `drawCellPrim`，计入 `m3debug.fallbacks`）；原桌面版的 `*Art` / `*Prim` 两套绘制已移除 |
| 图集 | atlas | 网页版把贴图打成一张 `atlas.webp` |
| 纯前端库 | `match3-pure` | `app/pure` 做成的内部库（原生 `-Wall` 编译；网页 wasm 与测试按源码编） |
| 元数据 | `m3Meta` | wasm 导出给 JS 的表现表、颜色、音效名 |
