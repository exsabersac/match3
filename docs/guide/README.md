# 框架与实现分析导读（docs/guide）

这一组文档把仓库里已有的设计说明串成**一条从头到尾的阅读路线**，方便分析整个游戏的框架和实现过程。
它们不重写已有文档的细节：每章先讲「这一层是什么、数据怎么流过、代码在哪」，细节再链接到
[architecture.md](../architecture.md)、[rules-pipeline.md](../rules-pipeline.md)、[testing.md](../testing.md)、
[web.md](../web.md)、[ui-art.md](../ui-art.md)、[haskell-features/](../haskell-features/) 等原文。

依据：`main` 上 `a045194` 时的源码与 git 历史。文中的路径都相对仓库根目录，`文件:行号` 指这个提交上的行号
（代码以后改动时行号可能漂移，函数名仍可搜）。

## 三条推荐路线

- **只想快速看懂框架（约 1 小时）**：01 → 03 的时序图 → 04 的前两节 → 05 的「共用纯逻辑」一节。
- **要改规则 / 加元素**：01 → 02 → 03 → 04（含触点清单）→ 07，再读 [architecture.md「元素框架与事件」](../architecture.md#元素框架与事件) 与 [domain.md](../domain.md)。
- **要改表现 / 前端**：01 → 03 → 05 → 06，再读 [ui-art.md](../ui-art.md)、[web.md](../web.md)、[ui-controls.md](../ui-controls.md)。

## 写法约定

- 「核实」指本组文档写作时在源码里逐条查过；查不到依据的地方写明「不确定」。
- 代码摘录只保留类型签名和关键几行，省略号 `…` 表示删去的字段 / 分支。
- 时间都是北京时间（UTC+8）。提交 SHA 用 7 位短号，可在 GitHub 上直接打开。
