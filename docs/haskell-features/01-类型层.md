# Haskell 特性展示 1：类型层（DataKinds、GADTs、类型族）

> 系列共六项：**1 类型层** · 2 类型类与抽象 · 3 效果与架构 · 4 惰性与递归模式 · 5 性能与并发 · 6 测试与光学。
> 本篇对应分支 `feat/hs-types`。游戏行为完全不变（金标准 `golden.txt`、元素查询快照 `element-queries.txt` 逐字节一致）。

## 0. 一句话

给「一步棋」里的盘面贴上**类型层的阶段标签**：交换后、消除后、下落后、补满。阶段之间只能经指定的转换函数走，
走错顺序（没下落就补子、有空洞还要消、锤子拿交换后的盘起手……）**编译不过**。

| 模块 | 改了什么 |
|------|----------|
| `src/Match3/Board/Phase.hs`（新） | 阶段种类 `Phase`、带阶段的盘面 GADT `Stage p`、类型族 `Repr` / 约束 `IsFull`、六个阶段转换函数 |
| `src/Match3/Board/Cascade.hs` | 每一轮的 `settleRound` 改为按阶段走：`Stage 'Cleared → fallStage → Stage 'Fallen → refillStage → Stage 'Full`；回放记录 `CascadeWave` 由 `waveOf` 拼，`cwHoles` 只收 `Stage 'Cleared` |
| `src/Match3/Game/Resolve.hs` | `MoveKind` 提升到类型层：类型族 `StartPhase`（每种操作从哪个阶段起手）、单例 `SMoveKind`；`Opening` 变成按起手阶段索引的 GADT；`resolveMove(With)` 的三个参数由同一个 `k` 约束 |
| `src/Match3/Game/Move.hs` / `Boosters.hs` | 调用处：交换用 `swapStage` 造出 `Stage 'Swapped`，锤子 / 十字传 `fullStage` 原盘 |
| `test/Spec/Phase.hs`（新） | 合法路径与原无标签函数逐项相等；7 个「编译不过」的写法用延迟类型错误变成测试 |

对外 API（`trySwap` / `useHammer` / `cascade*With` / `CascadeWave` / `MoveKind` …）一个都没改，前端、网页版、原有测试不用动。
唯一改了签名的是 `resolveMove` / `resolveMoveWith`，它们只在 `src/` 内部被 `Move` / `Boosters` 调用。

## 1. 这三个特性是什么

### 1.1 DataKinds：把值「提升」成类型

平常 `data Phase = Full | Swapped | Cleared | Fallen` 定义的是**类型** `Phase` 和它的四个**值**。
开了 `DataKinds` 之后，GHC 额外做一份「上一层」的拷贝：

| 层 | 平常 | DataKinds 额外得到 |
|----|------|------|
| 值 | `Full :: Phase` | — |
| 类型 | `Phase :: Type` | `'Full :: Phase`（一个**类型**，它的种类是 `Phase`） |
| 种类（kind） | `Type` | `Phase`（一个**种类**） |

`'Full` 这样的类型**没有值**，只拿来当标签：`Stage 'Full` 和 `Stage 'Cleared` 是两个不同的类型。
前面的单引号 `'` 表示「这是提升后的构造器」，不写也行（GHC 会猜），但 `-Wall` 会对歧义提醒，本仓库统一写上。

`Resolve` 里同样把**已有的** `MoveKind` 提升了：`'KindHammer` 是一个种类为 `MoveKind` 的类型。原来的值层 `MoveKind` 一点没变（原测试照用）。

### 1.2 GADT：每个构造器自己决定返回类型

普通 ADT 的构造器返回类型都一样；GADT（广义代数数据类型）允许每个构造器写出**精确**的返回类型：

```haskell
data Stage (p :: Phase) where
  AtFull    :: Board  -> Stage 'Full
  AtSwapped :: Board  -> Stage 'Swapped
  AtCleared :: MBoard -> Stage 'Cleared
  AtFallen  :: MBoard -> Stage 'Fallen
```

两个效果：

1. **构造时**：`AtCleared` 只能造出 `Stage 'Cleared`，而且里面一定是 `MBoard`（有空洞的盘）。
2. **匹配时**：在 `case s of AtCleared mb -> ...` 这个分支里，编译器**知道** `p ~ 'Cleared`（类型细化）。

`Opening` 也是 GADT：`OpenMatch :: Maybe Pos -> Opening 'Swapped` 规定「普通匹配起手」这个值只存在于 `Opening 'Swapped` 里。

### 1.3 类型族：类型层的函数

封闭类型族（closed type family）就是在类型上写的 `case`：

```haskell
type family Repr (p :: Phase) :: Type where
  Repr 'Full    = Board
  Repr 'Swapped = Board
  Repr 'Cleared = MBoard
  Repr 'Fallen  = MBoard

type family StartPhase (k :: MoveKind) :: Phase where
  StartPhase 'KindSwap     = 'Swapped
  StartPhase 'KindFreeSwap = 'Swapped
  StartPhase 'KindHammer   = 'Full
  StartPhase 'KindCross    = 'Full
```

编译器在类型检查时把 `Repr 'Cleared` 化简成 `MBoard`，把 `StartPhase 'KindHammer` 化简成 `'Full`。

### 1.4 单例（singleton）：把类型带到值层

类型在运行时会被擦掉，函数没法「看」一个类型参数 `k` 是什么。单例 GADT 给每个类型配**恰好一个**值：

```haskell
data SMoveKind (k :: MoveKind) where
  SKindSwap     :: SMoveKind 'KindSwap
  SKindHammer   :: SMoveKind 'KindHammer
  ...
```

传 `SKindHammer` 时，类型层得到 `k ~ 'KindHammer`（于是 `StartPhase k` 化简成 `'Full`），值层也能经 `moveKind` 取回普通的 `KindHammer` 去查步末表、扣道具次数。

### 1.5 三者怎么配合（`stageGrid` 这一行最能说明）

```haskell
stageGrid :: Stage p -> Repr p
stageGrid (AtFull b)     = b    -- 这个分支 p ~ 'Full，返回类型 Repr 'Full    = Board
stageGrid (AtCleared mb) = mb   -- 这个分支 p ~ 'Cleared，返回类型 Repr 'Cleared = MBoard
...
```

一个签名、四个分支各返回不同的类型：**GADT 匹配告诉编译器 p 是什么，类型族再算出返回类型**。
没有 GADT，分支里不知道 p；没有类型族，返回类型写不出来。

## 2. 为什么用在这里

### 2.1 一轮连锁：消除后 / 下落后的盘面都是 `MBoard`

一轮连锁 = 消除 → 下落（重力、边缘收集饼干、传送门）→ 补子。改动前三步之间的盘面类型是：

```
Board ──clear*──▶ MBoard ──settleDrainWith──▶ MBoard ──refillWith──▶ Board
```

中间两个都是 `MBoard = Array Pos (Maybe Cell)`。所以：

- `refillWith pol g mb`（**没下落就补子**）能编译：空洞会被补在原地，上面的宝石悬空；
- `settleDrainWith` 调两次能编译（多做一次重力 + 收集，计数会多算）；
- 回放记录 `CascadeWave` 的 `cwHoles` 要的是「消除后、下落前」的盘面（前端据此画「空洞」那一帧），
  误传下落后的盘面也能编译，回放画面就错了，而金标准里只存散列，不一定一眼看出。

这正是「类型一样、含义不同」的地方，用阶段标签区分最自然。`Board` 与 `MBoard` 的区别原来就有（满盘 / 有空洞），
`Repr` 类型族只是把它和阶段对上号。

### 2.2 一步棋的起手：交换类 vs 道具

`resolveMoveWith` 是交换与三种道具的公共结算。改动前签名是 `MoveKind -> Board -> Opening -> ...`，注释写着
「start = 第一轮之前的盘面（交换后 / 道具原盘）」——全靠调用方自觉：

- 玩家交换 / 自由交换：起手盘 = **交换后**的盘，起手可以是普通匹配、种子（彩虹 / 特殊合成）、变身；
- 锤子 / 十字：起手盘 = **原盘**（静止盘面，没有现成三连），起手只能是种子。

现在 `StartPhase` 把「操作种类 → 起手阶段」写成类型层的表，`Opening` 的 GADT 索引把「哪种起手只能接在交换后」写进类型。

### 2.3 没选的落点：类型索引的盘面尺寸

第 49 关起盘面是 5–10 的矩形（`Level` 记录里的 `lvlRows` / `lvlCols`），尺寸在**运行时**从关卡表读出来。
把尺寸放进类型（`Board (r :: Nat) (c :: Nat)`）就得在每次开局时用存在类型 + `KnownNat` 把它「藏起来再取出」，
所有接触盘面的函数（几十个，含前端与网页版）都要带上尺寸参数，坐标越界检查也得改成类型层的证明——
收益（越界在编译期报错）和改动面不成比例，而越界目前由 `inBounds` 一处把关、测试覆盖充分。所以这一项没做。

## 3. 改动前后

### 3.1 每一轮：`Match3.Board.Cascade.settleRound`

改动前：

```haskell
settleRound :: RandomGen g => Registry -> LevelHooks -> g -> Board -> (MBoard, Int, [Pos]) -> Int -> (Round, g)
settleRound reg hooks g b (mb, n, pos) w =
  let (settled, drained) = settleDrainWith reg hooks mb
      sites = map fst drained
      (b', g') = refillWith (activeRefill reg hooks) g settled
  in (Round (CascadeWave b pos sites mb b' (scoreForWave w n)) n (withDrained reg drained (hitsOn reg b pos)) sites, g')
```

注意 `CascadeWave b pos sites mb b' ...` 里 `mb`（消除后）和 `settled`（下落后）类型相同，写反了也能编译。

改动后（`src/Match3/Board/Cascade.hs` 第 154–170 行）：

```haskell
waveOf :: Stage 'Full -> [Pos] -> [Pos] -> Stage 'Cleared -> Stage 'Full -> Score -> CascadeWave
waveOf before cleared drained holes after =
  CascadeWave (stageGrid before) cleared drained (stageGrid holes) (stageGrid after)

settleRound :: RandomGen g => Registry -> LevelHooks -> g -> Stage 'Full -> (Stage 'Cleared, Int, [Pos]) -> Int -> (Round, g)
settleRound reg hooks g before (holes, n, pos) w =
  let (fallen, drained) = fallStage reg hooks holes                  -- 消除 → 下落
      (after, g') = refillStage (activeRefill reg hooks) g fallen    -- 下落 → 补子
      sites = map fst drained
      wave = waveOf before pos sites holes after (scoreForWave w n)
  in (Round wave after n (withDrained reg drained (hitsOn reg (stageGrid before) pos)) sites, g')
```

调用处（五处：匹配连锁、种子起手、飞碟吸收、皮带 / 步末后的补结算、单轮）从

```haskell
cr@(_, n, pos) = clearMatchesDetailedWith reg pref b
(r1, g1) = settleRound reg hooks g b cr wave
```

变成

```haskell
bS = fullStage b
cr@(_, n, pos) = clearStage (clearMatchesDetailedWith reg pref) bS
(r1, g1) = settleRound reg hooks g bS cr wave
```

步末挖洞原来手写 `setManyM (toM b) [(p, Nothing) | p <- holes]`，现在是 `digHoles holes bS`，同样得到 `Stage 'Cleared`。

### 3.2 一步棋：`Match3.Game.Resolve`

改动前：

```haskell
data Opening
  = OpenMatch (Maybe Pos)
  | OpenSeeds (Maybe Pos) [Pos]
  | OpenMorph (Maybe Pos) EndEffect [Pos]
  deriving (Eq, Show)

resolveMoveWith :: Registry -> MoveKind -> Board -> Opening -> GameState -> (GameState, Outcome, MoveTrace)
resolveMoveWith reg0 kind start opening gs = ...
```

改动后（`src/Match3/Game/Resolve.hs` 第 68–126 行）：

```haskell
type family StartPhase (k :: MoveKind) :: Phase where ...   -- 见 1.3

data Opening (p :: Phase) where
  OpenMatch :: Maybe Pos -> Opening 'Swapped
  OpenSeeds :: Maybe Pos -> [Pos] -> Opening p
  OpenMorph :: Maybe Pos -> EndEffect -> [Pos] -> Opening 'Swapped

deriving instance Eq (Opening p)      -- GADT 不能直接 deriving，用 StandaloneDeriving
deriving instance Show (Opening p)

resolveMoveWith
  :: IsFull (StartPhase k)
  => Registry -> SMoveKind k -> Stage (StartPhase k) -> Opening (StartPhase k) -> GameState -> (GameState, Outcome, MoveTrace)
resolveMoveWith reg0 sk startS opening gs =
  let kind = moveKind sk          -- 值层的 MoveKind：步末表、扣步数照旧
      start = stageBoard startS   -- 下面的结算代码一行没改
      ...
```

三个参数的类型都由同一个 `k` 决定。`IsFull (StartPhase k)` 约束在调用处 `k` 已知时自动化简成 `Board ~ Board` 成立；
它让函数体里能用 `stageBoard`（只对满盘阶段可用）。

调用处：

```haskell
-- Game.Move（玩家交换）
swappedS = swapStage p1 p2 (fullStage board0)      -- Stage 'Swapped
... resolveMoveWith reg SKindSwap swappedS opening gs   -- opening :: Opening 'Swapped

-- Game.Boosters（锤子）
resolveMoveWith reg SKindHammer (fullStage (gsBoard gs)) (OpenSeeds Nothing [p]) gs
```

## 4. 编译器能挡住哪些错误

下面每条都是真的类型错误（GHC 9.14.1 的原文，略去位置信息）。`test/Spec/Phase.hs` 把它们逐条写成了测试（做法见 4.1）。

| 写法 | 含义 | GHC 报错 |
|------|------|----------|
| `refillStage pol g cleared` | 没下落就补子 | `Couldn't match type ‘Cleared’ with ‘Fallen’` / `Expected: Stage Fallen, Actual: Stage Cleared` |
| `fallStage reg hooks fallen` | 下落两次 | `Couldn't match type ‘Fallen’ with ‘Cleared’` |
| `clearStage f cleared` | 有空洞的盘面再消一次 | `Couldn't match type ‘Cleared’ with ‘Full’` |
| `stageBoard cleared` | 把有空洞的盘当满盘取出 | `Couldn't match type ‘Array Pos (Maybe Cell)’ with ‘Board’ arising from a use of ‘stageBoard’` |
| `swapStage a b swapped` | 交换后的盘再交换一次（中间没结算） | `Couldn't match type ‘Swapped’ with ‘Full’` |
| `resolveMove SKindHammer (fullStage b) (OpenMatch Nothing) gs` | 锤子却要普通匹配起手 | `Couldn't match type ‘Swapped’ with ‘Full’` / `Expected: Opening (StartPhase KindHammer), Actual: Opening Swapped` |
| `resolveMove SKindHammer (swapStage a b (fullStage b0)) (OpenSeeds …) gs` | 锤子拿交换后的盘起手 | `Couldn't match type ‘Swapped’ with ‘Full’` / `Expected: Stage (StartPhase KindHammer), Actual: Stage Swapped` |
| `waveOf before pos sites fallen after s`（在 Cascade 内） | 回放的 `cwHoles` 记成下落后的盘面 | `Couldn't match type ‘Fallen’ with ‘Cleared’`（`waveOf` 不导出，这条没写成测试） |

另外，模块外**造不出**非法阶段：`Stage` 的构造器不导出，`Stage 'Cleared` / `'Fallen` / `'Swapped` 只能经转换函数得到。
（`fullStage :: Board -> Stage 'Full` 是公开的，因为任何 `Board` 本来就是满盘，这一步永远合法。）

### 4.1 「编译不过」怎么写成测试（不加依赖）

`test/Spec/Phase.hs` 顶部：

```haskell
{-# OPTIONS_GHC -fdefer-type-errors -Wno-deferred-type-errors #-}
```

- `-fdefer-type-errors`：类型错误不让编译失败，而是把出错的表达式换成「求值时抛出 `TypeError`」，消息就是本来的编译错误；
- `-Wno-deferred-type-errors`：关掉随之而来的警告，保持 0 警告。

测试对每个非法绑定 `evaluate`，断言抛出了 `TypeError`、且消息里点名了冲突的两个阶段。这就是 `should-not-typecheck` 库的原理，这里手写十几行。
注意只在这个测试模块里开，`src/` 一律正常编译；这个模块里的合法代码如果写错，也只会在运行时抛 `TypeError` 让测试失败，不会悄悄通过。

## 5. 取舍

- **运行时零代价、行为不变**。`Stage` 只是一层构造器包装，转换函数里调用的还是原来的 `clear*` / `settleDrainWith` / `refillWith`，
  随机数消耗顺序不变。验证：金标准 3373 行、元素查询快照 1666 行重新生成后与入库文件 `cmp` 逐字节相同；
  `phase_round_same_as_untyped` 在 40 个随机盘上比对带标签 / 不带标签两条路径的每个中间盘面与生成器状态。
- **信任边界在 `clearStage`**。它接受任何 `Board -> (MBoard, Int, [Pos])` 函数并把结果标成 `'Cleared`——类型只保证
  「从满盘出发、结果按消除后对待」，不保证你传进来的函数真的是「消除」。`fallStage` / `refillStage` 则直接调用唯一的实现，没有这个缺口。
- **只包住内部，不改公开类型**。`CascadeWave` 的字段、`cascade*With` 的参数仍是 `Board` / `MBoard`：前端 `ComboFx`、网页版 JSON、
  几百个测试都直接用它们，改成带标签的类型要连带改 `app/` 与 `web/hs`，而那些地方只读不写，收益小。代价是标签只在
  `settleRound` 一轮之内和 `resolveMove` 的入口处起作用，连锁循环本身（`go` 的盘面）仍是 `Board`，每轮开头用 `fullStage` 重新贴标签。
- **`MoveKind` 保留为普通枚举**。原测试里有 `[KindSwap, KindHammer, KindFreeSwap, KindCross]` 这样的列表，带索引的 GADT 放不进同一个列表；
  所以另做单例 `SMoveKind`，代价是 `moveKind` 这四行样板（`singletons` 库能自动生成，为此加依赖不值得）。
- **`Repr` 与 GADT 构造器有重复**：`AtCleared :: MBoard -> ...` 和 `Repr 'Cleared = MBoard` 说的是同一件事，写了两遍。
  `Repr` 换来的是 `stageGrid` 一个签名走天下、以及 `IsFull` 约束。也可以只用幻影类型 `newtype Stage (p :: Phase) = Stage (Repr p)`，
  不用 GADT；但那样函数没法按阶段做模式匹配，构造器也不再自带「这个阶段装什么」的说明。
- **错误消息**：大多数很直白（`Couldn't match type ‘Cleared’ with ‘Fallen’`），`stageBoard cleared` 那条会把 `MBoard` 展开成 `Array Pos (Maybe Cell)`。
  想更友好可以用 `GHC.TypeLits.TypeError` 写自定义报错（例如「盘面阶段 Cleared 还有空洞」），本次没做，留作以后。
- **语言扩展**：只在用到的模块里逐个开（`DataKinds`、`GADTs`、`KindSignatures`、`TypeFamilies`、`TypeOperators`、`ConstraintKinds`、`StandaloneDeriving`），
  没有改 `package.yaml` 的默认语言；网页版（`web/match3-web.cabal`，Haskell2010 + `-Werror`）照常编译。

## 6. 复习小抄

| 想表达 | 写法 | 本仓库位置 |
|--------|------|-----------|
| 一组标签当类型用 | `data Phase = ...` + `{-# LANGUAGE DataKinds #-}`，类型里写 `'Cleared` | `Board/Phase.hs` `Phase` |
| 每个构造器返回不同类型 | `data T (p :: K) where C :: ... -> T 'X` | `Stage`、`Opening`、`SMoveKind` |
| 类型层的 `case` | `type family F (p :: K) :: R where F 'X = ...` | `Repr`、`StartPhase` |
| 「满足某个类型等式」的约束 | `type IsFull p = (Repr p ~ Board)`（`ConstraintKinds`） | `Board/Phase.hs` `IsFull` |
| 把类型参数带到运行时 | 单例 GADT + 一个降级函数 | `SMoveKind` / `moveKind` |
| GADT 要派生实例 | `deriving instance Show (Opening p)`（`StandaloneDeriving`） | `Game/Resolve.hs` |
| 断言「这段写法编译不过」 | `-fdefer-type-errors` + `evaluate` + 捕获 `TypeError` | `test/Spec/Phase.hs` |

推荐按这个顺序读代码：`src/Match3/Board/Phase.hs`（整个文件不到 150 行）→ `Cascade.hs` 的 `settleRound` → `Resolve.hs` 的
`StartPhase` / `Opening` / `resolveMoveWith` 签名 → `test/Spec/Phase.hs` 的非法写法一节。
