## 0. 一句话

惰性求值让「无穷多个候选」成为一个普通的值：**拒绝采样**就是「无穷抽样流上的第一个合格者」，
**有限重试**就是「同一条流的前 24 项里找，找不到取第 25 项」——后面的抽样根本不会发生，生成器推进得和手写循环一模一样。
反过来，惰性也会在不该偷懒的地方堆出 thunk：回放器的帧计数和累积器、计数表的 `foldl` 各修了一处，并配了能复现的内存实验。
递归模式（`unfold` / `fold` / `hylo`）在流的构造里用了展开，在测试里手写 `Fix` / `cata` / `ana` / `hylo` 把回放器重写一遍对照，
并用实验数据说明为什么回放器**不**适合写成 hylo。

## 1. 这些特性是什么

### 1.1 惰性求值：值在被需要时才算，算过就记住

GHC 里一个表达式不会在绑定时求值，而是先变成一个 **thunk**（「等着算的东西」）；只有被 `case` 模式匹配（或者 `seq`、bang pattern）
需要时才算，而且只算到**弱首范式**（WHNF：最外层的构造器出来就停，比如 `(:)`、`(,)`、`Just`）。算完之后 thunk 被结果覆盖，
同一个值不会算第二次。

两个直接后果：

- **可以定义无穷的结构**：`iterate f x` 是一个无穷列表，只要消费者只看有限的前缀就没问题；
- **可以把「生成」和「挑选」分开写**：`find ok (iterate step x)` 里，`iterate` 不知道什么时候停，`find` 不知道值从哪来，
  惰性保证只生成 `find` 看到的那几个。

### 1.2 无穷流与余递归

列表 `[a]` 可能是空的，所以 `head` 是部分函数（GHC 9.8 起会对它报 `-Wx-partial` 警告）。
如果一个序列**按定义就是无穷的**（「再抽一次」永远可以做），就该用一个没有空构造器的类型：

```haskell
infixr 5 :>
data Stream a = a :> Stream a          -- 没有 []：headS / findS / splitAtS 都是全函数

unfoldS :: (s -> (a, s)) -> s -> Stream a
unfoldS step = go
  where
    go s = let (a, s') = step s in a :> go s'
```

`go` 的递归调用在构造器 `:>` 的**里面**：调用 `go s` 立刻返回 `a :> <thunk>`，尾部要等有人模式匹配才继续展开。
这种「每一步先交出一个构造器」的递归叫**余递归**（corecursion），它保证无穷展开也是**有生产力的**（productive）——
任何有限前缀都能在有限步内拿到。

### 1.3 递归模式：fold、unfold、hylo

几乎所有循环都可以拆成两半：

| 模式 | 列表版 | 一般形式 | 做什么 |
|------|-------|---------|--------|
| 折叠 catamorphism | `foldr` | `cata :: Functor f => (f a -> a) -> Fix f -> a` | 把一个结构一层层**消费**成一个值 |
| 展开 anamorphism | `unfoldr` | `ana :: Functor f => (a -> f a) -> a -> Fix f` | 从一个种子一层层**生成**一个结构 |
| 先展开再折叠 hylomorphism | `foldr f z . unfoldr g` | `hylo alg coalg = alg . fmap (hylo alg coalg) . coalg` | 生成一层、立刻消费一层，**不建中间结构** |

`Fix f` 是「把基函子 `f` 无限套下去」的不动点；基函子描述**一层**长什么样，递归交给 `Fix`。回放器的一层就是：

```haskell
newtype Fix f = Fix (f (Fix f))
data TickF st ev r = DoneF st | PlayingF [ev] r   -- 播完（终态），或者这一帧的事件 + 剩下的回放
  deriving (Functor)
```

`stepPlayer` 恰好就是一个余代数（coalgebra）`Player st -> TickF st ev (Player st)`；「数帧数、拼事件、取终态」是一个代数（algebra）
`TickF st ev (Int, [ev], st) -> (Int, [ev], st)`。`hylo alg coalg` 就是「播完整段并汇总」——和 `runPlayer` 是同一件事（测试逐项对照）。

### 1.4 严格性：什么时候惰性反而有害

惰性的代价是 thunk 本身要占内存。最经典的坑是**带累积器的左折叠**：

```haskell
foldl  (+) 0 [1 .. n]   -- 累积器一路是 thunk：(((0 + 1) + 2) + …)，最后才一口气算，n 层
foldl' (+) 0 [1 .. n]   -- 每一步先把累积器算到 WHNF 再往下走，常数空间
```

要点：

- `foldl'` / `seq` / bang pattern（`go !n …`）只把值算到 **WHNF**。累积器是元组时，`foldl'` 只保证元组构造器存在，
  元组里面的分量照样可以是 thunk（`Match3.Board.Refill.refillWith` 的 `(盘面, 生成器)` 累积器就是这样，见 §5）。
- GHC 的**严格性分析**（demand analysis）在 `-O` 下会自动把「反正最后都要算」的参数改成严格的，所以很多 `foldl` 在 `-O1`
  下没事——但这依赖优化器能看穿，一个值只出现在**惰性构造器的字段里**（比如最后返回的元组里）时就经常看不穿。
  §4 的实验里两种情况都有：`countsFromList` 的 `foldl` 在 `-O1` 下照样堆，`runPlayer` 的帧计数 `-O0` 堆、`-O1` 被救回来了。
- 惰性 / 严格只影响**什么时候算、占多少内存**，不影响纯函数的结果（只要不涉及 ⊥）。所以这一类改写的正确性很好验证：
  结果逐项相等，再单独量内存。

## 2. 为什么用在这里

**拒绝采样本来就是一条无穷流。** 「随机一盘，有三连就重来」的语义是：在 `g, g1, g2, …` 上依次抽样，取第一个合格的。
第 4 项前每个采样器都把「抽样」「换下一个生成器」「判定」「递归」缠在一个函数里；可玩盘的采样器是两层拒绝采样，
同样的四件事又写了一遍。现在 `draws sample g` 负责「无穷次抽样」，`findS ok` 负责「挑第一个」，采样器本身一行。

**有限重试是同一条流的前缀。** `ensurePlayableWith` 的旧写法是计数器 `go 24 … go 0`：前 24 次洗完要检查，
第 25 次洗完不检查直接用。这个「计数器何时归零、归零那一次检不检查」的细节很容易差一。写成流之后，
「前 24 次」就是 `splitAtS 24`，「第 25 次」就是剩下那条流的 `headS`，数字只出现一次；
惰性保证第 k 次合格时，k+1 次以后（包括兜底那次）根本不会洗，生成器只推进 k 次。

**回放器与计数表：严格性的真实落点。** `runPlayer` 被测试与网页版的离线核对（`Match3Web.Anim.animRunPlayer`）调用，
每帧推进一次，帧计数和事件累积器随帧数线性增长；`countsFromList` 是 `Map` 累积器上的 `foldl`，正是 §1.4 的经典形状。
两处的实际输入都很小（回放几十到几百帧、计数表几项），所以这是**卫生**而不是线上性能问题——改它们是因为
「左折叠 + 累积器」这种形状本来就该严格，而且改了之后不再依赖优化器能否看穿。

**hylo 放在测试里，不进 `runPlayer`。** 回放器在概念上就是「展开成帧、折叠出结果」，hylo 是它最直白的数学描述，
所以测试里手写一份对照；但 `runPlayer` 的消费者要的是「总帧数」这种**左折叠**，hylo 是右折叠，§4 的数据显示它在这里更费内存，
所以生产代码保留累积器循环。

**没有动的地方（以及原因）：**

- **连锁循环**（`cascadeMatchesFromM`）：第 3 项刚把它写成能力类程序，在严格的 `State` 里跑；把它改成惰性的轮次流
  就得换成惰性 `State` 或者把效果拆出来，等于推翻第 3 项。轮数也只有个位数，没有堆积问题。
- **补子**（`refillWith`）：随机数看起来能先预生成一条颜色流，但补子策略收的是 `RefillCtx`（这个空洞的位置和当前半满的盘面），
  策略可以按上下文决定抽不抽、抽几次，颜色流无法与位置无关地预先生成。
- **已经是惰性的代码**（不改，只在这里点名）：`findHintWith` 把所有候选交换写成一个列表、只取第一个，
  找到一手就不再试后面的；它的 `rowHas` / `colHas` 是元素惰性的 `Array`，每行 / 列的「已有三连？」最多算一次、用不到就不算——
  这是惰性数据结构当**记忆表**用。`Engine.Game.runActions` 是余递归的（先交出这一步的 `Step` 再递归），
  所以能吃无穷动作表、遇到结局就停（`lazy_counts_and_run_actions` 用 `repeat Reset` 验证）。

## 3. 改动前后

### 3.1 拒绝采样：手写尾递归 → `findS ok . draws sample`

改动前（`Match3.Board.Random`）：

```haskell
randomStableBoardSized rows cols g =
  let (b, g') = randomBoardSized rows cols g
  in if hasAnyMatch b then randomStableBoardSized rows cols g' else (b, g')

randomPlayableBoardSized rows cols g =
  let (b, g') = randomStableBoardSized rows cols g
  in if hasValidMove b then (b, g') else randomPlayableBoardSized rows cols g'
```

改动后：

```haskell
-- Engine.Stream
draws :: (g -> (a, g)) -> g -> Stream (a, g)
draws sample = unfoldS (\g -> let x@(_, g') = sample g in (x, g'))

findS :: (a -> Bool) -> Stream a -> a
findS ok = go
  where
    go (a :> rest)
      | ok a = a
      | otherwise = go rest

-- Match3.Board.Random
randomStableBoardSized rows cols = findS (not . hasAnyMatch . fst) . draws (randomBoardSized rows cols)
randomPlayableBoardSized rows cols = findS (hasValidMove . fst) . draws (randomStableBoardSized rows cols)
```

`draws` 的第 k 项是 `(第 k 盘, 抽完第 k 盘后的生成器)`，合格时返回的正是这一对，和旧写法返回的 `(b, g')` 相同。
可玩盘是两层流：外层每抽一次，内层就跑完一整次「无三连」拒绝采样。

### 3.2 自动洗牌：计数循环 → 流的前缀

改动前（`Match3.Game.Shuffle.ensurePlayableWith`，`reshuffle` 不变）：

```haskell
  | otherwise = go (24 :: Int) gs
  where
    go 0 g = let (board, g') = reshuffle g
             in g { gsBoard = board, gsGen = g', gsHint = Nothing, gsShuffled = True }
    go n g = let (board, g') = reshuffle g
                 g2 = g { gsBoard = board, gsGen = g', gsHint = Nothing, gsShuffled = True }
             in if hasValidMoveWith reg board then g2 else go (n - 1) g2
```

改动后：

```haskell
  | otherwise = fromMaybe (headS rest) (find (hasValidMoveWith reg . gsBoard) checked)
  where
    (checked, rest) = splitAtS 24 (iterateS reshuffleOnce (reshuffleOnce gs))
    reshuffleOnce g =
      let (board, g') = reshuffle g
      in g { gsBoard = board, gsGen = g', gsHint = Nothing, gsShuffled = True }
```

`iterateS reshuffleOnce (reshuffleOnce gs)` = 第 1 次、第 2 次……重洗后的状态，每次从上一次的生成器接着洗（与 `go` 把 `g2` 传下去相同）。
前 24 次里找第一个有可走步的，找不到就取第 25 次（不检查）。整个 `GameState`（含 `gsGen`）与旧写法逐项相等。

### 3.3 `runPlayer`：严格的帧计数、不存空事件表

```haskell
-- 改动前
runPlayer fastStep sm = go 0 []
  where
    go n acc p = case stepPlayer fastStep sm p of
      Done final -> (n + 1, concat (reverse acc), final)
      Playing p' evs -> go (n + 1) (evs : acc) p'

-- 改动后（模块加 {-# LANGUAGE BangPatterns #-}）
runPlayer fastStep sm = go 0 []
  where
    go !n acc p = case stepPlayer fastStep sm p of
      Done final -> (n + 1, concat (reverse acc), final)
      Playing p' [] -> go (n + 1) acc p'
      Playing p' evs -> go (n + 1) (evs : acc) p'
```

两处堆积：`n` 只在最后的元组里用到，没被优化掉时每帧多一个 `(n + 1)` thunk；`acc` 每帧压一个事件表，而绝大多数帧没有事件。
`concat` 本来就丢掉空表，所以不压空表结果不变。

### 3.4 `countsFromList`：`foldl` → `foldl'`

```haskell
countsFromList = foldl  (\c (k, n) -> bumpCount k n c) noCounts   -- 改动前
countsFromList = foldl' (\c (k, n) -> bumpCount k n c) noCounts   -- 改动后
```

### 3.5 测试里的 hylo（`test/Spec/Lazy.hs`）

```haskell
tickCoalg :: Int -> Stages st ev -> Player st -> TickF st ev (Player st)
tickCoalg fs sm p = case stepPlayer fs sm p of
  Done final -> DoneF final
  Playing p' evs -> PlayingF evs p'

tickAlg :: TickF st ev (Int, [ev], st) -> (Int, [ev], st)
tickAlg (DoneF st) = (1, [], st)
tickAlg (PlayingF evs ~(n, rest, st)) = (n + 1, evs ++ rest, st)   -- ~：先交出这一帧的事件

hyloPlayer    fs sm = hylo tickAlg (tickCoalg fs sm)
cataAnaPlayer fs sm = cata tickAlg . ana (tickCoalg fs sm)
```

测试断言 `runPlayer`、旧写法、`hyloPlayer`、`cataAnaPlayer` 四种跑法逐项相同（帧数、事件序列、终态），用例包括倒数阶段机、
固定提示队列（含 0 帧的提示、正常速度与加速）、每关开局一手的真实连锁回放。惰性代数里的 `~`（惰性模式）让 hylo
可以**边播边交出事件**：一个永不结束的阶段机，`take 5` 它的事件只展开 5 帧——`runPlayer` 和旧写法都要播完才返回，做不到。

## 4. 类型能挡住什么，挡不住什么（附严格性实验）

| 错误 | 改动前 | 改动后 |
|------|--------|--------|
| 对「无穷抽样」取头时忘了空的情况 | 列表上 `head` 是部分函数，`-Wx-partial` 警告；手写递归不会出这个问题，但也没有可复用的部件 | `Stream` 没有空构造器，`headS` / `findS` / `splitAtS` 都是全函数，没有要处理的空分支 |
| 重试次数差一（检查了 25 次 / 只洗 24 次） | 计数器 `go 24 … go 0` 的边界靠读代码 | 数字只出现在 `splitAtS 24` 一处；类型 `([GameState], Stream GameState)` 说明「前缀 + 一定还有下一个」 |
| 抽样用错生成器（接着用旧的 `g`） | 每个采样器自己传 `g'` | 生成器只在 `draws` 里传，采样器碰不到 |

**类型挡不住的：内存。** 严格性错误不改变结果，只改变内存曲线，编译器不会报任何东西。所以配了一个能复现的实验
`docs/haskell-features/demo/Strictness.hs`（不在任何构建目标里）：

```sh
b=$(mktemp -d); stack exec -- ghc -O1 -rtsopts -Wall -package-id "$(stack exec -- ghc-pkg --simple-output field match3 id)" -outputdir "$b" -o "$b/s" docs/haskell-features/demo/Strictness.hs
"$b/s" player-old 100000 +RTS -s     # 看 "maximum residency"
```

本机结果（GHC 9.14.1；回放 = 1000 万帧、10 万个事件；计数 = 500 万项；`player-new` 调的是库里的 `runPlayer`，库按 `-O1` 编译）：

| 实验 | 写法 | 最大驻留 -O0 | 最大驻留 -O1 |
|------|------|-------------:|-------------:|
| `player-old` | 第 4 项前的 `runPlayer` | 609 MB | 244 MB |
| `player-bang-only` | 只加 `!n`，空表照样入栈 | 244 MB | 244 MB |
| `player-new` | 第 4 项后的 `runPlayer` | 5.1 MB | 5.0 MB |
| `player-hylo` | hylo + 惰性代数（§3.5） | 1193 MB | 705 MB |
| `player-hylo-strict` | hylo + 严格代数（`let !m = n + 1`） | 465 MB | 457 MB |
| `counts-foldl` | 第 4 项前的 `countsFromList` | 458 MB | 412 MB |
| `counts-foldl'` | 第 4 项后的 `countsFromList` | 0.06 MB | 0.04 MB |

怎么读：

- **帧计数 thunk 链**：`-O0` 下 `player-old` → `player-bang-only` 省了 365 MB，就是 1000 万个 `(n + 1)`；`-O1` 下两者相同——
  GHC 自己把 `n` 改严格了。bang pattern 的价值是**不依赖优化器**。
- **累积器里的空表**才是 `-O1` 下的大头（244 MB → 5 MB）：这不是 thunk，是实打实的 1000 万个 cons 单元。
  严格性问题不只是「加个 `!`」，还要看累积器里存了什么。
- **`foldl` 在 `-O1` 下照样堆**：优化器没能把这个累积器改成严格的（为什么要看 Core，这里不展开）。
  「`-O` 会救 `foldl`」不能当成规律，该严格的地方自己写 `foldl'`。
- **hylo 在这里更差**：惰性代数要把每帧的元组和选择子 thunk 留到有人读帧数为止；严格代数没有帧计数的 thunk 链，但右折叠是非尾递归，
  1000 万层调用全在栈上（GHC 的栈也算进驻留）。`runPlayer` 要的是总帧数——一个**左折叠**，累积器循环（就是 `foldl'` 的形状）才对。
  hylo 的优势在结果本身被惰性消费时（§3.5 的无穷回放取前 5 个事件），这个优势 `runPlayer` 的调用方用不上。

## 5. 取舍

- **行为不变**。纯函数的求值顺序不影响结果；验证：金标准 3373 行、元素查询快照 1666 行重新生成后与入库文件 `cmp` 逐字节相同；
  原有 407 个测试全过，新增 5 个（共 412 个）；`make check`（网页版 state / anim 一致性 + e2e）通过。
- **新增一个类型 `Stream`，而不是用列表 + `iterate`**。代价是多一个模块和几个小函数；好处是「这串东西不会完」写进了类型，
  `headS` / `findS` 不需要「空了怎么办」的分支，也就不会有 `-Wx-partial` 警告或 `error "unreachable"`。
  `Stream` 只有采样与重试两个用户，所以没有给它写 `Functor` / `Foldable` 等实例（`Foldable` 对无穷结构本来也只有一半能用）。
- **`findS` 可能永远不返回**。这是拒绝采样的本义（旧的手写递归同样如此）；能否终止取决于合格的概率不为 0——
  `2×2` 这种根本不可能有可走步的盘面，两种写法都会死循环。自动洗牌用的是有界版本（`splitAtS` + 兜底），不受影响。
- **`refillWith` 的 `foldl'` 只到 WHNF**。它的累积器是 `(MBoard, g)`，`foldl'` 只保证元组构造器存在，里面的盘面更新和生成器
  仍是 thunk 链；但链长 = 本轮空洞数（≤ 81），每轮结束就被完整求值，所以不改，只在这里记一笔。真要改，写 `step (!mb, !g) p`。
- **严格化的两处都是卫生**。实际回放几十到几百帧、计数表几项，§4 的实验是放大一万倍后的样子；改它们是因为形状不对，
  不是因为线上出过问题。文档里给了实验命令，任何人都能复现数字。
- **hylo / `Fix` 只在测试里**。它是回放器最直白的数学描述，用来交叉验证很合适；但生产代码保留累积器循环，原因见 §4。
  同理，测试里的 `Fix` 没有放进 src——除了对照，库里没有第二个用户。
- **网页版**：`Engine.Stream` 和 `Engine.Playback` 都在 wasm 里（Haskell2010 + `-Wall -Werror`，`BangPatterns` 按模块打开）；
  wasm 产物单独一个提交。
