## 1. 这些特性是什么

### 1.1 van Laarhoven 透镜：一个函数，换函子就换用途

```haskell
type Lens s t a b = forall f. Functor f => (a -> f b) -> s -> f t
type Lens' s a = Lens s s a a

lens :: (s -> a) -> (s -> b -> t) -> Lens s t a b
lens get put f s = put s <$> f (get s)
```

一个透镜就是「给我一个处理焦点的函数，我把它用到整体上」。读和写只是选了不同的函子：

| 想做 | 选的函子 | 写法 |
|------|---------|------|
| 读 | `Const a`（`fmap` 什么都不做，把焦点原样带出来） | `view l s = getConst (l Const s)` |
| 改 | `Identity` | `over l f = runIdentity . l (Identity . f)` |
| 收集 | `Const [a]` / `Const (Endo [a])`（要 `Monoid`） | `toListOf` |
| 找第一个 | `Const (First a)` | `preview` |

因为透镜就是函数，**复合就是 `(.)`**：`gsBoardL . cellAt p` 是「对局状态里盘面上的第 p 格」，方向和 OO 的 `.field.field` 一样从外到里。

### 1.2 遍历与棱镜

- **遍历** `Traversal s t a b = forall f. Applicative f => (a -> f b) -> s -> f t`：同样的形状，只是要求 `Applicative`，
  所以可以有零个或多个焦点（`traverse` 本身就是一个遍历）。透镜是遍历的特例（`Functor` 约束更弱），可以直接混用。
- **棱镜** 描述和类型的一种情形：能拆（可能失败）也能造。van Laarhoven 形式要把「函数箭头」抽象成一个 profunctor：

  ```haskell
  type Prism s t a b = forall p f. (Choice p, Applicative f) => p a (f b) -> p s (f t)
  class Choice p where
    dimapP :: (a -> b) -> (c -> d) -> p b c -> p a d
    right' :: p a b -> p (Either c a) (Either c b)
  prism :: (b -> t) -> (s -> Either t a) -> Prism s t a b
  prism bt seta = dimapP seta (either pure (fmap bt)) . right'
  ```

  取 `p = (->)` 时它就是一个遍历（`preview` / `over` 都能用）；取 `p = Tagged`（只有输出的「箭头」）时可以倒着跑，得到构造函数 `review`。
  所以 `overlay . _Fog` 是一个 `Traversal' Cell Int`，`review _Fog 2 == Fog 2`。

### 1.3 定律

光学的类型只说明了「形状」，好不好用要看定律（全部在 `test/Spec/Optics.hs` 里用 QuickCheck 检查）：

| 光学 | 定律 |
|------|------|
| 透镜 | put-get：`view l (set l a s) == a`；get-put：`set l (view l s) s == s`；put-put：`set l b (set l a s) == set l b s` |
| 遍历 | 恒等：`t Identity == Identity`；合成：`t (Compose . fmap g . f) == Compose . fmap (t g) . t f` |
| 棱镜 | `preview p (review p a) == Just a`；`preview p s == Just a` ⇒ `review p a == s` |

### 1.4 QuickCheck：性质、`Arbitrary`、`shrink`、状态机模型

- **性质**是一个返回 `Bool` / `Property` 的函数，QuickCheck 随机生成输入跑 100 次；`classify` 统计用例分布（看有没有真的覆盖到想测的情形）。
- **`forAll gen`** 显式给生成器；**`Arbitrary` 实例**把生成器和 **`shrink`**（「比这个更简单的候选」）绑在类型上。
  失败时 QuickCheck 沿 `shrink` 反复缩小反例，直到每个更简单的候选都通过——报出来的是一个**小**反例。
  `forAll` 不带 shrink；`forAllShrink gen shr` 两者兼得。
- **`expectFailure`**：「这条性质必须能找到反例」——用来把「某条定律在某种前提下不成立」固定成一条测试。
- **状态机模型测试**：生成一串命令，同时在真实实现和一个「显然正确」的简单模型上执行，每一步比较可观察的状态。
  命令序列是列表，QuickCheck 默认会删命令、缩小单个命令，所以反例通常缩到两三步。

## 2. 为什么用在这里

**叠层代码是典型的「嵌套和类型 + 按构造器复制」。** `Match3.Grass` 的四个揭层函数（迷雾 / 锁链 / 火箭冰冻 / 窗帘）
逐字相同——「找与 seeds 正交相邻、带这种叠层的格；1 层就去掉并计数，否则层数减一」——只差 `Fog` / `Chain` / `Freeze` / `Curtain` 四个构造器；
三个蔓延函数（藤 / 巧克力 / 蒸汽）、两个邻消函数（巧克力 / 蒸汽）、七个位置查询同理；`Match3.Types.Overlay` 里每种叠层一对 `hasX` / `xLayers`。
差别是「哪一种叠层」——它是**和类型的一个情形，带一个 `Int` 层数**，这正是棱镜 `Prism' CellOverlay Int` 描述的东西。
把棱镜作为参数传进去，四份变一份。普通的高阶函数也能做（传一对「拆 / 造」函数），但那正是手写的棱镜，而且不能和 `cellAt` / `overlay` 用 `(.)` 复合。

**GameState 的派生读数本来就是透镜。** 第 7 刀把五个字段（飞碟 / 皮带 / 传送门 / 地毯 / 地面层）收进 `gsLevelElems`，
留下了 `gsUfos :: GameState -> [Ufo]` 与 `setUfos :: [Ufo] -> GameState -> GameState` 这样的 get / set 对——这就是「虚拟字段」，
按定义是一个透镜。原有测试 `qc_level_elems_readers_roundtrip` 只检查了战役开局盘上的 get-put；透镜定律把 put-get、put-put 也补上，
还量出了 get-put 的前提（§4）。

**结算里「每种操作花什么」是按种类选字段。** `Resolve` 的步数与道具次数原来是四个分支的记录更新（交换扣 1 步；锤子 / 自由交换 / 十字各扣自己的次数）。
写成 `kindCharges :: MoveKind -> Traversal' GameState Int`（交换 = `ignored`，没有焦点）后只剩一行，「交换没有道具次数」也写进了类型的取值里。

**测试缺的是缩小与模型。** 原有 34 个 QuickCheck 性质（`Spec.Properties` 24 个，其余散在 5 个模块里）的盘面都来自 `forAll` + 生成器（`Spec.Properties` 里固定 8×8），没有一个能缩小，失败时报一整张盘；
撤销历史只有「撤销一步再重做」的往返性质，**没有任何测试检查快照上限**（§3.5 的变异检查证实了这一点）。

**没有动的地方（以及原因）：**

- **元素实例里的同类代码**（`Element/Builtin/Layer.hs` 的 `Gem c k _ ov -> Gem c k n ov` 等五六处）：它们是第 2 项元素类框架里各元素自己的放置 / 读数，
  一处一个构造器、没有复制，换成光学只是换写法，不改。
- **桌面版 `app/UI/Env.hs` 的 `setUfos … . setPortals …` 链**：只写不读，已经很清楚；光学在这里没有收益。
- **`Boosters` 的次数判断**（`gsHammers gs <= 0`）：读一个字段，`view gsHammersL gs` 并不更好。
- **`microlens` / `lens`**：不引。`microlens` 没有棱镜，`lens` 依赖太重；手写的类型与它们**同形**（都是 van Laarhoven），
  以后要换只需改 import。
- **分数单调、目标进度单调、撤销往返、补子无空洞**：原有性质已经覆盖（`qc_goal_progress_monotone` 等），不重复。

## 3. 改动前后

### 3.1 揭层：四份 → 一份，叠层种类是一个棱镜

```haskell
-- 旧（Match3.Grass，迷雾；锁链 / 冰冻 / 窗帘各一份，只把 Fog 换掉）
chipAdjacentFogExcept b seeds except = foldl hit (b, 0) targets
  where
    targets = nub [q | p <- nub seeds, q <- ortho b p, q `notElem` except, hasFog (at b q)]
    hit (board, n) p = case at board p of
      Gem col kind ice (Just (Fog layers))
        | layers <= 1 -> (setAt board p (Gem col kind ice Nothing), n + 1)
        | otherwise -> (setAt board p (Gem col kind ice (Just (Fog (layers - 1)))), n)
      _ -> (board, n)

-- 新
chipAdjacentLayerExcept :: Prism' CellOverlay Int -> Board -> [Pos] -> [Pos] -> (Board, Int)
chipAdjacentLayerExcept layer b seeds except = foldl hit (b, 0) targets
  where
    targets = nub [q | p <- nub seeds, q <- ortho b p, q `notElem` except, has (overlay . layer) (at b q)]
    hit (board, n) p = case at board p ^? overlay . layer of
      Just layers
        | layers <= 1 -> (stripAt board p, n + 1)
        | otherwise -> (board & cellAt p . overlay . layer .~ layers - 1, n)
      Nothing -> (board, n)

chipAdjacentFogExcept = chipAdjacentLayerExcept _Fog
chipAdjacentChainExcept = chipAdjacentLayerExcept _Chain
-- …
```

`cellAt p . overlay . layer .~ layers - 1` 一路读进去、改最里面的 `Int`、再一路重建回来：重建 `Fog`（`review _Fog`）、重建 `Gem`（`gemOverlay`）、
写回盘面（`boardSet`）——旧代码里手写的三层构造器都在光学里。棱镜作为**参数**传进来时要用两次（`has` 用 `Const`，`.~` 用 `Identity`），
所以参数类型是多态的 `Prism' …`（rank-2，模块要开 `RankNTypes`）；只用一次的地方（`positionsWith :: Getting Any Cell a -> …`）传单态的 `Getting` 就够了。

### 3.2 蔓延与邻消：叠层值本身就是选择子

```haskell
spreadLayer :: CellOverlay -> Board -> Board
spreadLayer o b =
  let sources = positionsWith (overlayIs o) b                     -- overlayIs o = overlay . only o
      targets = nub [q | p <- sources, q <- ortho b p, bareGem (at b q)]
  in foldl plant b targets
  where
    plant board p
      | bareGem (at board p) = board & cellAt p . gemOverlay .~ Just o
      | otherwise = board

spreadVines = spreadLayer Vine; spreadChoco = spreadLayer Choco; spreadSteam = spreadLayer Steam
```

`bareGem cell = preview gemOverlay cell == Just Nothing`——「是宝石（有叠层槽）且槽是空的」，两层 `Maybe` 各有含义。
`Match3.Types.Overlay` 的读数同样一行一个：`hasFog = has (overlay . _Fog)`、`fogLayers = fromMaybe 0 . preview (overlay . _Fog)`、
`clearOverlay = set gemOverlay Nothing`。

### 3.3 GameState：字段透镜、派生读数透镜、按种类选字段

```haskell
-- Match3.Game.State
gsMovesL = lens gsMoves (\gs v -> gs {gsMoves = v})
gsUfosL  = lens gsUfos (flip setUfos)               -- 派生读数：本来就有的 get / set 对

-- Match3.Game.Resolve（旧：四个分支）
spend g = case kind of
  KindSwap -> g {gsMoves = gsMoves gs - 1 + bonusMoves}
  KindHammer -> g {gsMoves = gsMoves gs + bonusMoves, gsHammers = gsHammers gs - 1}
  KindFreeSwap -> g {gsMoves = gsMoves gs + bonusMoves, gsFreeSwaps = gsFreeSwaps gs - 1}
  KindCross -> g {gsMoves = gsMoves gs + bonusMoves, gsCrossClears = gsCrossClears gs - 1}
-- 新
spend g = g & gsMovesL %~ (\m -> m - kindCost kind + bonusMoves) & kindCharges kind %~ subtract 1

kindCharges :: MoveKind -> Traversal' GameState Int
kindCharges kind = case kind of
  KindSwap -> ignored          -- 交换不耗道具：没有焦点的遍历
  KindHammer -> gsHammersL
  KindFreeSwap -> gsFreeSwapsL
  KindCross -> gsCrossClearsL
```

（`g` 是 `gs` 的记录更新，没碰 `gsMoves` / 道具次数，所以 `g` 上读到的值与旧代码读 `gs` 相同；金标准逐行锁定。）

### 3.4 自定义 `Arbitrary` 与 `shrink`

```haskell
newtype AnyBoard = AnyBoard Board           -- 任意行列 1–10
instance Arbitrary AnyBoard where
  arbitrary = AnyBoard <$> genAnyBoard
  shrink (AnyBoard b) = map AnyBoard (shrinkBoard b)

-- 先去最后一行 / 最后一列（保持矩形），再逐格简化
shrinkCell (Gem c k i o) = [Gem c k i Nothing | isJust o] ++ [Gem c k 0 o | i > 0] ++ [Gem c Normal i o | k /= Normal] ++ [Gem C1 k i o | c /= C1]
shrinkCell _             = [mkGem C1]
```

每个候选都「严格更简单」（行列数或格子复杂度下降），所以缩小一定会停。

| `qc_inv_history_matches_list_model` | 撤销历史的状态机测试：玩具计数器（`test/Toy.hs`）套 `withHistory`，上限 1–4，随机命令串（走一步 / 撤销），每一步的当前状态、快照栈、是否接受、能否撤销都与一个十几行的列表模型相同 |

**变异检查**（每次改一处，跑整套 429 个测试）：

| 改坏的地方 | 失败的测试 | QuickCheck 报出的反例 |
|-----------|-----------|---------------------|
| `chipAdjacentLayerExcept` 的 `layers <= 1` 改成 `< 1`（1 层叠层永远揭不掉） | 13 个：9 个原有单元测试（四种叠层的「邻消揭完」「层数减一」与锁链 + 冰冻同揭）、元素查询快照 2 个、金标准、`qc_optics_grass_same_as_legacy` | 缩小 4 次后是一张 **6×1** 的盘，只有一格 `Chain 1`：新写法得到 `Chain 0`、计数 0，旧写法去掉锁链、计数 1 |
| `_Curtain` 的构造写成 `Chain`（复制粘贴错） | 7 个：原有 `curtain_layer_decrement` / `surprise_blast_peels_adjacent`、元素查询快照 2 个、金标准、`qc_optics_prism_laws`（第 1 个用例就失败：`preview _Curtain (review _Curtain 3) = Nothing`）、`qc_optics_grass_same_as_legacy` | — |
| `Engine.History.pushHistory` 的 `take (hpLimit p)` 改成 `take (hpLimit p + 1)`（快照多留一份） | **只有** `qc_inv_history_matches_list_model`；原有 417 个测试全过 | 缩小 8 次后：上限 2，命令 `[Inc 1, Inc 1, Inc 1]`，第三步后真实历史有 3 份快照、模型只有 2 份 |

三次都是逐个改、各跑一遍整套。前两行原有测试也能抓到（叠层规则有单元测试和金标准兜着），新性质的价值是报出的反例更小、直接指向光学；
第三行是这一项最有说服力的数据：撤销上限的差一错误，原有的 417 个测试（含撤销往返、终局后撤销等）一个都没抓到。

另外核对了 §4 表里两条「编译不过」：`view overlay (mkGem C1)` 报 `No instance for ‘Monoid CellOverlay’`，`review gsMovesL 3` 报类型不匹配（`MovesLeft -> f0 MovesLeft` 对不上 `Tagged`）。

## 4. 类型能挡住什么，挡不住什么（附实测）

| 错误 | 改动前 | 改动后 |
|------|--------|--------|
| 揭层时改错了叠层种类（锁链的函数里写了 `Fog`） | 四份代码各写一遍构造器，抄错能编译 | 种类只在 `chipAdjacentLayerExcept _Chain` 一处出现 |
| 对「可能没有」的焦点用了「一定有」的读法 | `case` 漏分支只有 `-Wincomplete-patterns` 警告 | `view overlay cell` **编译不过**：`view` 要 `Getting CellOverlay`，即 `Const CellOverlay` 要是 `Applicative`，而 `CellOverlay` 不是 `Monoid`；只能用 `preview` 拿 `Maybe` |
| 用透镜去「构造」 | — | `review` 只收棱镜（`Tagged` 不是函数箭头，透镜实例化不到它），`review gsMovesL 3` 编译不过 |
| 交换也扣了道具次数 | 四个分支各自写 | `kindCharges KindSwap = ignored`：交换在类型层面就「没有可扣的字段」 |
| 光学不守定律（`_Curtain` 构造成 `Chain`、`cellAt` 写错格） | — | **类型挡不住**：形状对、定律错。靠 §3.5 的定律性质（变异检查里第 1 个用例就失败） |

**定律有前提，QuickCheck 帮你找到前提。** 派生读数 `gsUfos` 是「按名字找 ufo 元素，没有就当空表」，写入 `setUfos` 是「同名替换，没有就追加」。
所以元素不在 `gsLevelElems` 里时，`set gsUfosL (view gsUfosL s) s` 会**多出一个空的 ufo 元素**——get-put 不成立：

```
+++ OK, failed as expected. Falsified (after 1 test):
["belt","portal","carpet","bomb_shapes","rainbow_combos","cookie_drop","ground"]
  -> ["belt","portal","carpet","bomb_shapes","rainbow_combos","cookie_drop","ground","ufo"]
```

更隐蔽的是：`Show GameState` 按旧字段名打印读数，两边打印**完全相同**，只有 `Eq`（比较 `gsLevelElems`）能看出差别。
游戏里碰不到这种状态——开局的 `startLevelsWith` 总是带全部内置元素，`qc_optics_state_lens_laws` 在局中状态上三定律全过——
所以不改实现（改了会让 `gsLevelElems` 的内容变化，元素查询快照会变），而是把前提写进注释、用 `expectFailure` 把反例固定成测试。
put-get 与 put-put 在这种状态上仍然成立（追加之后再写是替换）。

**缩小有多大用。** 同一个变异（`layers < 1`）在改成 `forAllShrink` 之前报的是一张 6×6、满是各种叠层的盘和两串十几个坐标；
之后是 6×1、只有一格带锁链。没有缩到 1×1，是因为 seeds / except 是在盘面之后生成的：盘面每缩一次，后面的坐标重新生成，
QuickCheck 只保留「仍然失败」的那些候选——缩小是贪心的局部搜索，不保证最小。

**实测**（本机 8 核，GHC 9.14.1，`-O1`）：

| 项 | 第 6 项前（`dc4cbed`） | 第 6 项后 |
|----|------:|------:|
| 测试数 | 417 | 429（+7 光学、+5 不变量） |
| 整套墙钟（默认并行） | 9.0 – 9.9 s | 8.1 – 8.8 s |
| 新增 12 个性质合计 | — | 约 0.3 s |
| 金标准生成（单线程） | 6.29 – 6.55 s | 6.34 – 6.42 s |
| `Match3.Grass` 行数 | 342 | 234 |

整套测试多了 12 个反而略快，是 box 负载不同造成的噪声，不是光学的功劳。光学在 `-O1` 下通常会被内联成和手写 `case` 差不多的代码（本项没有逐个看 Core）；
叠层函数不在热路径上（第 5 项的剖析里不到 1 %），金标准时间的差别在噪声范围内——**这一项没有性能收益，也没有可测的损失**。

## 5. 取舍

- **行为不变**。验证：金标准 3373 行、元素查询快照 1666 行重新生成后与入库文件 `cmp` 逐字节相同；原有 417 个测试全过，新增 12 个（共 429 个）；
  `make check`（网页版 state / anim 一致性 + e2e）通过。
- **手写光学而不是引库**。`Engine.Optics` 160 行、只依赖 base，网页版（wasm）不多一个包。代价是没有 `lens` 的上千个组合子、
  没有 Template Haskell 自动生成字段透镜（这里 5 个字段透镜是手写的，各一行）；类型与 `lens` / `microlens` 同形，要换只改 import。
  `microlens` 本来就没有棱镜（也就没有 `review`），这一项的核心用法它做不了。
- **`RankNTypes`**。把光学当参数传（`chipAdjacentLayerExcept :: Prism' … -> …`）是 rank-2 类型；网页版是 Haskell2010，
  用到的 6 个 src 模块逐个写了 `{-# LANGUAGE RankNTypes #-}`。类型错误信息会出现 `forall f. Functor f => …`，比手写 `case` 难读——这是光学的通病。
- **`cellAt` 只对界内坐标守定律**。它包的是 `boardAt` / `boardSet`，越界读报错（与旧代码相同）。`lens` 库会用 `ix p :: Traversal'`（越界没有焦点），
  这里没有改语义，保持「透镜 + 调用方保证界内」，测试也只生成界内坐标。
- **派生读数透镜是「有前提的透镜」**（§4）：不改实现，前提写在 `Match3.Game.State` 的注释里并有测试固定。
- **状态机模型很小**。`Engine.History` 本身只有 90 行，模型（`modelStep`）十几行，看上去像把实现重抄一遍；价值不在模型多聪明，
  而在**随机命令串 + 缩小**能走到手写用例想不到的组合（上限 1 时连续三步、空历史上撤销、`Reset` 不记快照穿插其中），
  变异检查证明了这一点。模型用的是玩具计数器，三消本身的撤销往返仍由原有的 `qc_undo_redo_roundtrip` 覆盖。
- **原有性质没有改成 `Arbitrary`**。34 个旧性质继续用 `forAll` + 原来的生成器（改它们不改变覆盖、只改变失败时的报告），
  新性质用自定义 `Arbitrary`；两套并存，`Spec.Support.Arbitrary` 复用旧的 `genCell` / `genColor`。
- **网页版**：`Engine.Optics`、`Match3.Types.Optics` 进了 wasm 的模块列表；wasm 产物单独一个提交。

## 6. 复习小抄

| 想要 | 写法 | 本仓库的例子 |
|------|------|-------------|
| 一个字段 / 虚拟字段 | `lens getter (\s v -> s {field = v})` | `gsMovesL`、`gsUfosL = lens gsUfos (flip setUfos)` |
| 读 / 改 / 写 | `s ^. l`、`s & l %~ f`、`s & l .~ v` | `g & gsMovesL %~ …` |
| 零到多个焦点 | `Traversal'`；`traverse` 本身就是 | `cells`、`gemOverlay` |
| 和类型的一种情形 | `prism' 构造 (\s -> case s of C x -> Just x; _ -> Nothing)` | `_Fog`、`_Gem` |
| 没参数的构造器 | `only Grass :: Prism' CellOverlay ()` | `overlayIs o = overlay . only o` |
| 可能没有的读 | `s ^? t`（`preview`）/ `has t s` | `at board p ^? overlay . layer` |
| 某种情况下什么都不改 | `ignored` | `kindCharges KindSwap` |
| 一路改到最里层 | `board & cellAt p . overlay . _Fog .~ n` | `chipAdjacentLayerExcept` |
| 把光学当参数 | 参数类型写 `Prism' s a`，开 `RankNTypes` | `chipAdjacentLayerExcept _Chain` |
| 检查定律 | put-get / get-put / put-put；遍历恒等 + 合成；棱镜两条往返 | `test/Spec/Optics.hs` |

| 固定一个已知反例 | `expectFailure` | `qc_optics_level_field_get_put_needs_invariant` |
| 看覆盖 | `classify cond "label"` | 「74 % some layer fully peeled」 |
| 状态机模型测试 | 随机命令串，真实实现与列表模型逐步比较 | `qc_inv_history_matches_list_model` |
| 证明测试有用 | 改坏一处，看谁失败、反例多小 | §3.5 的变异检查 |
