## 0. 一句话

盘面上有四种「邻格顺序」：
- 上下左右：邻消、蔓延、飞碟吸附；
- 右下左上：飞碟移动；
- 上左右下：蔓延来源；
- 右下：交换枚举。

它们散在核心库八处手写的四元 / 二元坐标列表里（桌面版另有三处），彼此不同，而且金标准依赖每一种的先后。但代码里看不出「这里的顺序是刻意的」。这一项做了四件事：

- **方向**：用一个和类型 `Dir` 表示，四种顺序各起一个名字。
- **坐标遍历**：「盘上所有满足条件的格在哪」原来写成先列坐标、再逐个回盘面读格，现在改成带坐标的折叠。这补上了第 2 项提到的「`Foldable` 只给格子、不给坐标」的缺口。
- **像素坐标**：UI 边界上像素的 x / y 各是一个 newtype，像素和格子坐标不能再互相冒充。
- **日期**：每日挑战的年 / 月 / 日各是一个 newtype，月和日写反就是类型错误。

没有新依赖，没有新模块，`web/match3-web.cabal` 的模块列表不变。

## 1. 这些特性是什么

### 1.1 方向是和类型，顺序是数据

```haskell
data Dir = North | South | West | East
  deriving (Eq, Ord, Show, Enum, Bounded)

stepDir :: Dir -> Pos -> Pos          -- 行向下增长：North = 行 − 1
dirBetween :: Pos -> Pos -> Maybe Dir -- stepDir 的逆；不相邻时 Nothing
neighborsIn :: [Dir] -> Pos -> [Pos]
```

方向从坐标增量 `(-1, 0)` 变成了一个有四个值的类型。派生的 `Enum` / `Bounded` 给出 `[minBound .. maxBound]`，即全部方向。

**顺序本身是一个普通的列表值**：`[North, South, West, East]`。一种「邻格顺序」从「某一行列表推导里四个元组的排列」变成了一个有名字、能比较、能在测试里写死的值：

```haskell
upDownLeftRight    = [North, South, West, East]  -- 邻消 / 蔓延 / 飞碟吸附
readingOrder       = [North, West, East, South]  -- 蔓延来源：邻格按行主序排好
clockwiseFromRight = [East, South, West, North]  -- 飞碟移动
rightAndDown       = [East, South]               -- 枚举相邻格对，每对只数一次
```

### 1.2 带坐标的折叠（FoldableWithIndex 的形状）

`Foldable` 的 `foldMap :: Monoid m => (a -> m) -> t a -> m` 只把元素交给回调。`indexed-traversable` 的 `FoldableWithIndex i t` 多给一个下标：

```haskell
ifoldMap :: Monoid m => (i -> a -> m) -> t a -> m
```

这里只为 `Grid` 写了这一组，没有建类：

```haskell
ifoldMap       :: Monoid m => (Pos -> a -> m) -> Grid a -> m
ifoldr         :: (Pos -> a -> b -> b) -> b -> Grid a -> b
ifoldl'        :: (b -> Pos -> a -> b) -> b -> Grid a -> b
positionsWhere :: (a -> Bool) -> Grid a -> [Pos]
```

它们直接走 `Array` 的 `assocs`。二元组下标的 `range` 是字典序，也就是行主序，所以顺序与 `boardPositions` 完全相同（测试逐项比对）。

### 1.3 坐标的每个分量一个 newtype

```haskell
newtype PxX a = PxX a   -- 像素横坐标（对应列）
newtype PxY a = PxY a   -- 像素纵坐标（对应行）
gridCellAt     :: Integral a => GridGeom a -> PxX a -> PxY a -> Maybe (Int, Int)
gridCellOrigin :: Num a => GridGeom a -> (Int, Int) -> (PxX a, PxY a)

newtype Year = Year Int; newtype Month = Month Int; newtype Day = Day Int
dailySeed :: Year -> Month -> Day -> Int
```

newtype 在运行时与被包的类型表示相同，没有开销。类型检查时它们互不相同，而且**故意不给 `Num` 实例**：
- 字面量 `gridCellAt g 25 15` 也编译不过，必须写出 `PxX 25`；
- 位置写对了名字才对得上。

## 2. 为什么用在这里

**同样是「四个邻格」，顺序有四种，而且都不能统一。**
- `Obstacles.adjacentWhere` 按「每个清除格的上、下、左、右」收集再 `nub`，削层与清除格的先后由它决定；
- 蔓延来源（`spreadPairs`）取「上、左、右、下」里第一个同类格，即邻格中行主序最靠前的一个，写进步末效果，表现层据此决定藤蔓从哪边长出来；
- 飞碟没吸到东西时按「右、下、左、上」挑第一个界内格移过去；
- 提示搜索和引擎的合法动作对每格只配右邻与下邻。

§3.4 的变异检查显示，把其中任何一种换成另一种，金标准都会变。原来这些顺序只是一行里四个元组的排列，相似到让人想「统一一下」。现在每种都有名字、有注释写明谁在用，测试把四个值写死。

**坐标遍历的旧写法要回盘面读格。** `[p | p <- boardPositions b, isSnail (getCell b p)]` 先生成坐标，再用坐标回数组取元素。
`Foldable` 帮不上忙，因为它不给坐标（第 2 项 §5 记下了这个缺口，说「为此加依赖或新类不值得」）。
手写四个函数不需要依赖，也不需要类，这些调用点都变成一个谓词：`positionsWhere isSnail b`。

**UI 边界上有三套坐标：像素 (x, y)、格子 (行, 列)、日期 (年, 月, 日)，都是几个相邻的 Int。**
- `gridCellAt g px py` 收两个裸的 `a`，`gridCellOrigin` 回一个 `(a, a)`：把 (行, 列) 当 (x, y) 传、或者 x / y 写反都能编译，而且在正方形棋盘上很难被测出来。
- `dailySeed 2026 29 9`（月、日写反）能编译，得到种子 20263009，是另一局游戏。

**没有动的地方（以及原因）：**

- **模式同义词（PatternSynonyms / ViewPatterns / `COMPLETE`）**：yu 明确排除了这部分。`Snail dr dc` 的构造器、字段、`Show` 一律不变（金标准按它打印；而且毛球 / 雪怪的选格散列 `Builtin.Common.boardSeed` 散列的就是 `show board`，改 `Show` 会直接改变第 43 / 45 关的对局，见 `Spec.BoardSeed`）。方向写法只加在 API 层：`mkSnailFacing East == Snail 0 1`，`snailFacing (Snail 0 1) == Just East`。蜗牛爬行仍按 `(dr, dc)` 计算，因为构造器允许任意整数，`Dir` 只覆盖四个单位步。
- **格子坐标仍是 `(Int, Int)`**：`Pos` 遍布全部规则代码、回放 JSON、网页版，换成 newtype 改动面太大。这里只保证像素与格子不能互相冒充，格子内部的「行在前」仍靠约定，以及 `stepDir` / `dirDelta` 写死的方向。
- **`Engine.GridUI.orthoAdjacent` 仍单独写一份**：`Engine.*` 只依赖 base（测试 `engine_layer_is_game_agnostic` 扫描 import），不能用 `Match3.Types.Board.Dir`。它与 `Grid.adjacent` 逐对相同，`grid_dir_basics` 和原有的 `grid_ui_geometry_matches_legacy_layout` 都有对照。
- **同时读两张盘的遍历**：`Tally.carpetVacateSeedsWith`、`Actor.tickRun` 的 `ticked`、`spreadPairs` 的外层都比较「之前 / 之后」两张盘，带坐标的单盘折叠帮不上，保持 `p <- boardPositions before`（`spreadPairs` 的外层从行 × 列两重生成器收成了 `q <- boardPositions before`，顺序相同）。
- **其他没改的写法**：
  - `chameleonShift` 是带着变化中的盘面的 `foldl`，回调读的是原盘 `b0`，改成 `ifoldl'` 只省一次读格，没改；
  - `snowBosses` 要按坐标调 `bossAt b p`，没改；
  - `Combos` / `Boosters` / `Gem` 里「整行 / 整列」的坐标列表（`boardColIndices`）不是邻格，没改。
- **测试里原有的 `p <- boardPositions b`**：不改，它们是对照的一方。

## 3. 改动前后

### 3.1 邻格顺序：八份手写列表 → 四个具名值

```haskell
-- 之前（Match3.Obstacles / Grass / Ufo 各一份）
orthoNeighbors (r, c) = [(r - 1, c), (r + 1, c), (r, c - 1), (r, c + 1)]
ortho b (r, c) = filter (inBounds b) [(r - 1, c), (r + 1, c), (r, c - 1), (r, c + 1)]
-- 之后
orthoNeighbors = neighborsIn upDownLeftRight
ortho = neighborsInBounds upDownLeftRight
```

```haskell
-- 之前（Match3.Ufo.moveUfo）
let (r, c) = pos
    cands = filter (inBounds b) [(r, c + 1), (r + 1, c), (r, c - 1), (r - 1, c)]
-- 之后
let cands = neighborsInBounds clockwiseFromRight b pos
```

```haskell
-- 之前（Match3.Element.Event.spreadPairs）
| r <- boardRowIndices before, c <- boardColIndices before, let q = (r, c)
, …
, let srcs = [n | n <- [(r - 1, c), (r, c - 1), (r, c + 1), (r + 1, c)], inBounds before n, …]
-- 之后
| q <- boardPositions before
, …
, let srcs = [n | n <- neighborsInBounds readingOrder before q, …]
```

```haskell
-- 之前（Match3.Engine 的合法动作；Board.Match 的提示搜索同形，少最后一行）
, (r, c) <- boardPositions b, let p = (r, c)
, q <- [(r, c + 1), (r + 1, c)], inBounds b q
, adjacent p q
-- 之后
, p <- boardPositions b
, q <- neighborsInBounds rightAndDown b p
```

`Grid.adjacent` 也由方向定义：`adjacent p q = isJust (dirBetween p q)`，与原来的 `(|Δr| = 1 ∧ Δc = 0) ∨ (|Δc| = 1 ∧ Δr = 0)` 逐对相同。

### 3.2 坐标遍历：先列坐标再读格 → 带坐标的折叠

```haskell
-- 之前
snailPositions b = sort [p | p <- boardPositions b, isSnail (at b p)]
extractDecorWith reg b =
  [CellDecor p cell | p <- boardPositions b, let cell = getCell b p, keepOnShuffleWith reg cell]
magicStones b = [(p, k) | p <- boardPositions b, Custom "magic_stone" (CustomState k) <- [getCell b p]]
-- 之后
snailPositions b = sort (positionsWhere isSnail b)
extractDecorWith reg = ifoldMap (\p cell -> [CellDecor p cell | keepOnShuffleWith reg cell])
magicStones = ifoldMap (\p cell -> [(p, k) | Custom "magic_stone" (CustomState k) <- [cell]])
```

`snailPositions` 的 `sort` 保留了。行主序就是 `Pos` 的 `Ord` 顺序，所以它其实是恒等，但删掉它要另外论证，收益是零。

### 3.3 UI 边界

```haskell
-- 之前（UI.Layout）
pixelToCell mx my = gridCellAt boardGrid (fromIntegral mx) (fromIntegral my)
cellOrigin = gridCellOrigin boardGrid
-- 之后：签名不变，桌面版其余代码一行不改
pixelToCell mx my = gridCellAt boardGrid (PxX (fromIntegral mx)) (PxY (fromIntegral my))
cellOrigin = pxXY . gridCellOrigin boardGrid
```

`UI.Layout` 是桌面版里唯一调 `Engine.GridUI` 像素换算的地方，所以 newtype 只在这一层包 / 拆。SDL 的绘图调用仍收 `(CInt, CInt)`。

### 3.4 为什么行为不变，以及哪些测试守着

逐条论证：

- **邻格顺序**：每个具名值和它替换的列表是同一组方向、同一个顺序（`grid_dir_basics` 写死四个值）。`neighborsInBounds ds b = filter (inBounds b) . neighborsIn ds`，与原来的「先列四格再 `filter (inBounds b)`」相同。
- **`Engine` 去掉的 `adjacent p q`**：候选 q 是 p 的右邻或下邻，`adjacent p q` 恒真，去掉不改变列表。
- **坐标遍历**：`assocs` 的顺序 = `range (bounds a)` = 行主序 = `boardPositions`；`positionsWhere ok` 用 `ifoldr` 按这个顺序过滤，结果与列表推导逐项相同（惰性也相同，可以只取前缀）。
- **像素 / 日期**：只是在参数外面包一层 newtype，函数体的算术一字未改。

## 4. 类型能挡住什么，挡不住什么

| 错误 | 改动前 | 改动后 |
|------|--------|--------|
| 像素 x / y 传反：`gridCellAt g y x` | 能编译；正方形棋盘上只在非对角处出错 | 类型错误：`Couldn't match expected type: PxX Int with actual type: PxY a0` |
| 把格子 (行, 列) 或裸数字当像素传 | 能编译 | 类型错误：`No instance for 'Num (PxX Int)' arising from the literal '25'` |
| 把 `gridCellOrigin` 的结果当 (行, 列) 用 | 能编译（都是二元组） | 结果是 `(PxX a, PxY a)`，要经 `pxXY` 才变成裸二元组 |
| 每日挑战月 / 日写反：`dailySeed (Year 2026) (Day 29) (Month 9)` | 三个 Int，能编译，另一局游戏 | 类型错误：`Couldn't match expected type 'Month' with actual type 'Day'` |
| 某处邻格顺序抄错（例如飞碟移动写成上下左右） | 四元组排列错了也能编译 | 顺序只在四个具名值里写一次。**用错名字类型挡不住**（都是 `[Dir]`），靠 `grid_dir_basics` 写死的值、各对照性质与金标准 |
| `Engine.GridUI` 内部把行列写反 | 能编译 | 仍能编译：格子还是 `(Int, Int)`，函数体内的解构类型看不出来，靠 §3.4 的两条测试 |
| 坐标遍历回盘读格时读错盘（`p <- boardPositions b0` 却 `getCell b p`） | 能编译 | 改写过的单盘遍历不再回盘读格，写不出这个错；双盘的几处（§2）仍是原写法 |

表里的错误信息是用一个只为验证而写的小文件、对本分支 `stack ghc -- -fno-code` 得到的（没有入库）。

## 5. 取舍

- **行为不变**。验证：
  - 金标准、元素查询快照逐字节相同（没有重新生成）；
  - 原有 435 个测试全过，新增 7 个，共 442 个；
  - `stack build --test --ghc-options=-Werror`（库、桌面版、测试）0 警告；
  - `make check`（网页版构建 + 状态 / 动画一致性 + e2e）通过。
- **动了桌面版 `app/UI` 的四个文件，没有动 `web/hs` 与 `app/pure`**。没有新增 `src` 模块，`web/match3-web.cabal` 不变。
  `make check` 重建 `web/dist` 后只有 `match3-web.wasm` 与入库版本不同（核心源码变了），`atlas.webp` 与其余文件逐字节相同；本分支没有提交重建的 `web/dist`（与前几项一样）。
- **`Dir` 放在 `Match3.Types.Board`**（`Pos` 所在的模块），不另开模块：新模块要同步进网页版的 cabal 模块列表，而这几个定义与 `Pos` 本来就是一体。
- **`step` 叫 `stepDir`**：`step` 是很多模块 `where` 里的局部函数名（`Game.Resolve`、`Element.Registry`、`Board.Refill` …），它们都无限定地 import `Match3.Types`。导出 `step` 会让 `-Wname-shadowing` 在这些地方报警。
- **方向构造器叫 `North` / `South` / `West` / `East`**，不叫 `N` / `S` / `W` / `E`，也不叫 `Up` / `Left`（后者与 `Either` 的 `Left` / `Right` 冲突）。单字母太容易与别处的构造器或类型变量读混。
- **不建 `FoldableWithIndex` 类**：仓库里只有 `Grid` 一个容器需要它，`MBoard = Array Pos (Maybe Cell)` 只在一轮沉降内部用。建类要么上函数依赖 / 类型族，要么引入 `indexed-traversable`，都换不来什么。函数名沿用那个库的（`ifoldMap` / `ifoldr` / `ifoldl'`），以后真要换成库，调用点不用改。
- **newtype 不给 `Num`**：给了 `Num`，字面量能直接传（`dailySeed 2026 9 29` 照常编译），但字面量写反（`dailySeed 2026 29 9`）也能编译，正好是要挡的错误。测试与调用点因此多写了 `Year` / `Month` / `Day`（共十几处）。
- **测试里的旧副本**：`LegacyGeometry` 的函数体照抄 49d57ad，不经过任何新 API（否则对照就成了自己比自己）。模块内部、不导出的三处写法（毛球、同色变色龙、魔法石）没法直接调用新代码，测试抄的是新源码里同一行表达式，对照的是「改写这一步」。

## 6. 复习小抄

| 想要 | 写法 | 本仓库的例子 |
|------|------|-------------|
| 有限个方向 | 和类型 + `deriving (Enum, Bounded)`，`[minBound .. maxBound]` 列全 | `Dir` |
| 让「顺序是刻意的」看得见 | 顺序写成一个有名字的列表值，测试写死 | `upDownLeftRight` / `readingOrder` / `clockwiseFromRight` / `rightAndDown` |
| 两格之间的方向 | 在全部方向里 `find` | `dirBetween`，`adjacent = isJust . dirBetween` |
| 遍历时要坐标 | FoldableWithIndex 形状的 `ifoldMap` / `ifoldr`，走 `assocs` | `positionsWhere isSnail b` |
| 几个相邻的同类型参数不许写反 | 每个分量一个 newtype，不给 `Num` | `PxX` / `PxY`、`Year` / `Month` / `Day` |
| 在边界上包 / 拆 | 只在一层（`UI.Layout`）包 / 拆，外面签名不变 | `cellOrigin = pxXY . gridCellOrigin boardGrid` |
| 不改构造器也能提供新写法 | API 层的智能构造器 / 读数 | `mkSnailFacing` / `snailFacing` |
| 证明重构不改行为 | 旧代码逐字副本 + QuickCheck 对照 + 变异检查 | `Spec.Support.LegacyGeometry`、§3.4 |
