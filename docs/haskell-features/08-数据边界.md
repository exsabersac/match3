## 0. 一句话

关卡记录、放置参数、格子类型这几处是「外面的数据进到规则代码」的边界。原来每处都各有一个缺口：

- **关卡记录**只查行列：皮带、传送门、飞碟、地毯、地面层、掉落口、放置表都没人查。放置表越界要等开局时 `placeAllWith` 报错，而且它碰到第一处就停（`Either`）。
- **放置参数**在 12 个放置函数里各手写一遍 `case args of [AInt n] -> …`。有的要求参数正好这么多，有的只看头一个、后面多出来的不管。两种写法长得几乎一样，代码里看不出哪个是刻意的。
- **格子类型**（`Color` / `GemKind` / `CellOverlay` / `CellContents` / `Outcome`）都 `deriving Generic`，但没有任何地方用它。新加一个构造器之后，测试生成器、注册表、`cellFace`、桌面版的绘制表、网页版的结局编码要不要跟着加，只能靠人记。
- **「不会为空」的列表**：`Engine.Effect.beats` 分出来的每一组都不会为空，但类型是 `[Effect]`。

这一项做了四件事：

- **Applicative 校验**：手写一个 `Validation e a`，只有 Applicative、没有 Monad，所有检查一次跑完、一次报全。
- **放置参数解析器**：一个 Applicative / Alternative 小解析器 `ArgP`，「精确匹配」和「前缀匹配」成了两个有名字的跑法。
- **Generic 覆盖测试**：在测试里用 `GHC.Generics` 的 `conName` 列出每个类型的全部构造器，检查每张表都有对应项。实例用 DeriveAnyClass，一个类型一行。
- **NonEmpty**：`beats` 的每组是 `NonEmpty Effect`。

没有新依赖，没有新的 `src` 模块，`web/match3-web.cabal` 的模块列表不变。

## 1. 这些特性是什么

### 1.1 Applicative 校验，以及为什么它不能是 Monad

```haskell
data Validation e a = Failure e | Success a

instance Semigroup e => Applicative (Validation e) where
  pure = Success
  Failure e1 <*> Failure e2 = Failure (e1 <> e2)   -- 两边都失败：错误拼起来
  Failure e1 <*> Success _  = Failure e1
  Success _  <*> Failure e2 = Failure e2
  Success f  <*> Success a  = Success (f a)
```

和 `Either e` 的唯一区别在第一行：`Either` 碰到左边的 `Left` 就停，`Validation` 两边都看、把错误拼起来。`validateLevel` 是一串 `<*` 连起来的独立检查，所以一关里有多少处问题就报多少处。

**它不能有合法的 Monad 实例。** Monad 定律要求 `(<*>) = ap`，其中 `ap mf mx = do { f <- mf; x <- mx; pure (f x) }`。再看 `Failure e1 >>= k`：左边没有值，`k` 跑不了，只能返回 `Failure e1`。所以 `ap (Failure e1) (Failure e2) = Failure e1`，而上面的 `<*>` 给的是 `Failure (e1 <> e2)`，两者不相等。

两条路：
- 给 Monad，那 `<*>` 就得退回「碰到第一处就停」，和 `Either` 一模一样；
- 不给 Monad，保留「一次报全」。

这里选后者。真有「后一项检查要用前一项的结果」的情况，用 `validationToEither` 转成 `Either` 去写。代价是 `do` 写法用不了（§4 有编译器的报错）。

### 1.2 Applicative / Alternative 参数解析器

```haskell
newtype ArgP a = ArgP {runArgP :: [Arg] -> Maybe (a, [Arg])}

argInt   :: ArgP Int                          -- 取一个整数参数
argColor :: ArgP Color                        -- 取一个颜色参数
exactArgs  :: ArgP a -> [Arg] -> Maybe a      -- 解析成功，且参数正好用完
prefixArgs :: ArgP a -> [Arg] -> Maybe a      -- 解析成功即可，剩下的忽略
```

- **Applicative**：从左往右依次取，例如 `Maker <$> argColor <*> argInt`。
- **Alternative**：`<|>` 左偏，只在这一步失败时改试右边。所以 `argInt <|> pure 1` 的意思是「有整数就取，没有就缺省 1」。
- **跑法和解析器分开**：同一个解析器既可以要求参数正好用完，也可以只看头部。原来这个区别藏在 `[AInt n]` 和 `(AInt n : _)` 两种模式的写法里，现在是 `exactArgs` 和 `prefixArgs` 两个名字。

不需要 Monad：放置参数里没有「后一个参数的类型取决于前一个参数的值」的情况。

### 1.3 用 GHC.Generics 列出构造器

`deriving Generic` 给出类型的「表示」`Rep a`：
- `D1` 包着整个类型；
- `:+:` 是构造器之间的「或」；
- `C1` 包着一个构造器，它的元数据带构造器名（`conName`）。

在 `Rep` 上写一个类，就能对任何派生了 Generic 的类型列出全部构造器：

```haskell
class GCons f where
  gconNames :: Proxy f -> [String]
  gconOf    :: f p -> String

instance GCons f => GCons (D1 d f)                 -- 透过类型这一层
instance (GCons f, GCons g) => GCons (f :+: g)     -- 左右两边拼起来
instance Constructor c => GCons (C1 c f) where     -- 取构造器名，不看字段
  gconNames _ = [conName (undefined :: C1 c f ())]
  gconOf m = conName m
```

面向使用者的类 `Constructors` 用 DefaultSignatures 给出基于 Generic 的默认实现，于是每个类型的实例只要一行（DeriveAnyClass + StandaloneDeriving）：

```haskell
deriving anyclass instance Constructors CellContents
```

还有一个 `GNullary`：对全是无参构造器的类型，按定义顺序列出全部值。`GemKind` 没有派生 `Enum` / `Bounded`，测试靠它枚举五种宝石。

### 1.4 NonEmpty

`Data.List.NonEmpty.NonEmpty a = a :| [a]`，至少一个元素。`NE.groupWith f` 把相邻、`f` 值相同的元素分成组，返回 `[NonEmpty a]`。组非空这件事写在了类型里。

## 2. 为什么用在这里

**关卡数据是手写的大表，错误往往不止一处。** 49 关的皮带、传送门、飞碟、掉落口都写在 `Levels.Campaign` 里。
- 原来只有行列有检查。
- 放置表越界要到开局 `placeStatic` 才报错，而且只报第一处。
- 皮带格写到盘外不会报错：`Conveyor` 照样移位，结果是静默的错误行为。

一次报全对改表的人最有用：一关改坏了三处，一次全看见。

**只收现有数据都满足的不变量。** 这一项不改行为，所以每条检查都先拿全部关卡和两年的每日关跑过（测试 `level_validation_all_levels_valid` 锁定），有关卡不满足的检查就不加。最明显的例子是皮带：
- 第 10 关「传送」的皮带是第 3 行一条直线，首尾不相邻，`Conveyor` 按「末格回到首格」移位，照常工作；
- 所以只查「至少 2 格、每格在盘内、同一条皮带不重复」，**不查首尾相邻、连成环、相邻两格要挨着**。

**放置参数的两种语义原来只差一个下划线。**
- `case args of [AInt n] -> …`：多一个参数就不放。
- `case args of (AInt k : _) -> …`：多一个参数也照放。

12 个函数里两种都有，而且都是刻意的（§3.2），但从代码上分不出「这里是精确匹配」还是「这里随手写成了前缀」。改成 `exactArgs` / `prefixArgs` 之后，语义写在名字里。

**Generic 早就派生了，一直没用。** 新加一个格子构造器，编译器只会在穷尽的 `case` 处给出不完全匹配的警告。下面这些表和生成器不报错：
- 测试生成器 `genCell` 漏掉它，所有 QuickCheck 性质就再也碰不到这种格；
- 桌面版的 `UI.CellTable` 漏掉它，这种格就画成空白；
- 网页版的 `encodeOutcome` 是 `case`，有警告；但它在 `web/hs`，不在 `stack test` 的构建里。

用 Generic 列出构造器之后，测试拿「全部构造器」去对照每张表。

**没有动的地方（以及原因）：**

- **`Conveyor.Belt` 仍是 `[Pos]`**：
  - 注释说「至少 2 格」，可是 `NonEmpty` 只保证至少 1 格，挡不住这条不变量；
  - `gsBelts` 会出现在 `GameState` 的 `Show` 里（金标准逐步打印），还经过视图模型 `bvBelts :: [[Pos]]`、网页 JSON、桌面 `drawBelt`、光学测试和关卡表字面量；
  - 换成 `NonEmpty` 会改 `Show` 输出（`(3,0) :| [...]`），金标准就变了。
  - 所以「至少 2 格」改在加载边界上查（`BeltTooShort`），类型不动。
- **放置表里的未知元素名不在 `validateLevel` 里查**：`Levels.Level` 在注册表之下（注册表依赖它），看不到注册表。未知名字仍由开局的 `placeAllWith` 报（全部关卡开局都有测试覆盖）。
- **`placeWith` / `placeAllWith` 仍是 `Either PlaceError`**：它们是逐格写盘的折叠，后一格依赖前一格写过的盘，本来就是顺序的。越界这类能提前查的，已经挪到 `validateLevel` 里一次报全了。
- **测试盘面的 QuasiQuoter 没做**：要给测试加 `template-haskell` 依赖，还要写一个盘面文本的解析器加报错位置，不算便宜。现有测试的盘面大多由 `boardFromRows` 加几个辅助函数造，收益有限。
- **`Generic` 只在测试里用**：src 里派生的 `Generic` 一行不动，没有新增任何运行时用 Generic 的代码（性能和 `Show` 都不受影响）。

## 3. 改动前后

### 3.1 关卡校验

```haskell
-- 之前：只查行列
checkLevelDims :: Level -> Either String Level
-- 之后：全部检查，一次列全
validateLevel :: Level -> Validation [LevelIssue] Level
validateLevel l =
  l
    <$ validateDims l
    <* each (zip [0 ..] (lvlBelts l)) belt
    <* each (zip [0 ..] (lvlPortals l)) portal
    <* each (zip [0 ..] (lvlUfos l)) (\(i, u) -> inside (UfoOutOfBounds i) (ufoCell u))
    <* each (lvlCarpets l) (inside CarpetOutOfBounds)
    <* dups CarpetDuplicate (lvlCarpets l)
    <* each (lvlGround l) ground
    <* dups GroundDuplicate (map fst (lvlGround l))
    <* each (zip [0 ..] (lvlDrops l)) drop1
    <* each (zip [0 ..] (lvlPlacements l)) place1
```

| 检查 | `LevelIssue` |
|------|-------------|
| 行列在 5–10 之内 | `BadDims`（文字与原 `checkLevelDims` 逐字节相同） |
| 每条皮带至少 2 格、格在盘内、同一条皮带不重复 | `BeltTooShort` / `BeltOutOfBounds` / `BeltDuplicate` |
| 传送门两端在盘内、两端不是同一格 | `PortalOutOfBounds` / `PortalSameCell` |
| 飞碟初始格在盘内 | `UfoOutOfBounds` |
| 地毯格在盘内、不重复 | `CarpetOutOfBounds` / `CarpetDuplicate` |
| 地面层格在盘内、不重复、层数 ≥ 1 | `GroundOutOfBounds` / `GroundDuplicate` / `GroundNoLayers` |
| 掉落口至少一格、格在盘内、保持数 ≥ 1 | `DropNoCells` / `DropOutOfBounds` / `DropKeepNonPositive` |
| 放置表每一格在盘内 | `PlacementOutOfBounds` |

渲染出的文字用「；」连接。只有行列一处问题时，`checkLevel` 与 `checkLevelDims` 的文字相同。

`lookupLevel` 从 `assertLevelDims` 换成 `assertLevel`：
- 对现有关卡，两者都原样返回关卡记录；
- 对坏关，error 的消息从「只说尺寸」变成「列出全部问题」。

### 3.2 放置参数：12 处手写 case → `ArgP`

```haskell
-- 之前（Obstacle.layersPlace）
layersPlace con args _ = case args of
  [AInt n] -> Just (con (max 1 n))
  [] -> Just (con 1)
  _ -> Nothing
-- 之后
layersPlace con args _ = con <$> exactArgs (max 1 <$> argInt <|> pure 1) args
```

```haskell
-- 之前（Actor 的果汁机）
\args _ -> case args of
  [AColor c, AInt n] -> Just (Maker c (max 1 n))
  [AColor c] -> Just (Maker c 3)
  _ -> Nothing
-- 之后
\args _ -> exactArgs (Maker <$> argColor <*> (max 1 <$> argInt <|> pure 3)) args
```

```haskell
-- 之前（Collectible 的变色龙）
\args cell -> case (args, cell) of
  (AColor c : _, _) -> Just (chameleonCell c)
  (_, Gem c _ _ _) -> Just (chameleonCell c)
  _ -> Nothing
-- 之后：先看参数，没有颜色再看原格（Maybe 的 <|>）
\args cell -> chameleonCell <$> (prefixArgs argColor args <|> gemColor cell)
```

每一处都保持原来的语义：

| 放置函数 | 位置 | 接受的参数 | 跑法 |
|---------|------|-----------|------|
| `customEntry`（气泡、毛球） | `Registry` | 头一个是整数就用它，否则缺省 1 | **前缀**（`fromMaybe 1 (prefixArgs argInt args)`） |
| `layersPlace`（石头 / 宝箱 / 蜂蜜 / 蛋糕 / 保险箱） | `Obstacle` | `[]` → 1；`[AInt n]` → `max 1 n` | 精确 |
| 双面块 | `Obstacle` | `[AColor f, AColor b]` | 精确 |
| 魔法石 | `Obstacle` | 头一个整数夹到 0–3，否则 0 | **前缀** |
| 雪怪 Boss | `Obstacle` | `[AInt hp, AInt q]`，再检查 1 ≤ hp ≤ 255、0 ≤ q < 4（`guard`） | 精确 + 范围 |
| 果汁机 | `Actor` | `[AColor c]` → 3；`[AColor c, AInt n]` → `max 1 n` | 精确 |
| 蜗牛 | `Actor` | `[AInt dr, AInt dc]` | 精确 |
| 倒计时 | `Actor` | `[AInt n]`，颜色取原格（宝石或倒计时） | 精确 + 看原格 |
| `colorPlace`（气球 / 染色瓶） | `Common` | `[AColor c]` | 精确 |
| 冰层 | `Layer` | `[AInt n]`，原格须是宝石 | 精确 + 看原格 |
| `layeredOverlay`（迷雾 / 锁链 / 火箭冰冻 / 窗帘） | `Layer` | `[AInt n]`，原格须是宝石 | 精确 + 看原格 |
| 变色龙 | `Collectible` | 头一个是颜色就用它，否则取原格宝石的颜色 | **前缀** + 看原格 |

前缀匹配的三处（`customEntry`、魔法石、变色龙）原来都写成 `(x : _)`，可见是刻意的：它们都有缺省值，多给的参数不影响。其余九处原来都是固定长度的列表模式。

### 3.3 Generic 覆盖测试

`Constructors` 对五个类型各一行 `deriving anyclass instance`。测试拿 `conNamesOf` 给出的全部构造器名对照：

- **生成器**：从 `genCell` 抽 6000 个样本。每个本体构造器的权重约 1/31，漏掉某一个的概率小于 1e-80。检查本体、宝石种类、叠层的构造器集合都等于全集；`genOverlay`、`genColor` 同样检查。
- **注册表**：
  - 每个本体构造器的代表格，元素名落在槽位一致的条目上；
  - 每种宝石种类（由 `GNullary` 枚举）、每种叠层的名字互不相同，槽位一致；
  - 每个代表都满足解码往返 `toCell . elementOf reg = id`。
- **`cellFace`**：每个本体构造器的类型标签互不相同（网页 JSON 的 `"t"`）；每种宝石种类的 `"k"`、每种叠层的 `"o"` 也互不相同。
- **桌面 `UI.CellTable`**：`app/` 不在测试的源码目录里，所以用源码扫描。每个内置本体名、每种宝石种类名都要是 `cellTable` 的键，每个已注册的自定义名字都要是 `customTable` 的键。
- **网页 `encodeOutcome`**（源码扫描）：每个 `Outcome` 构造器都要有 `tag "构造器名"`。

### 3.4 NonEmpty

```haskell
-- 之前
beats :: [Effect] -> [(Int, [Effect])]
beats [] = []
beats (e : es) =
  let (same, rest) = span ((== efBeat e) . efBeat) es
  in (efBeat e, e : same) : beats rest
-- 之后
beats :: [Effect] -> [(Int, NonEmpty Effect)]
beats = map (\g -> (efBeat (NE.head g), g)) . NE.groupWith efBeat
```

`NE.groupWith` 和原来的 `span` 写法一样，只合并相邻的同节拍效果，不排序。唯一的调用方 `Playback.effectCues` 取 `toList`，它的签名和结果都不变。

### 3.5 为什么行为不变，以及哪些测试守着

> **后来的变化**：死代码清理删除了 `LegacyBoundary`（见[旧副本对照的去留](../testing.md#旧副本对照的去留)）。`qc_argp_placers_match_legacy` → `argp_placers_pinned`（21 个元素名 × 11 组参数 × 2 种格，结果写死），`qc_beats_nonempty_matches_legacy` → `beats_examples_pinned`（含节拍倒序 `[2, 1, 0]`）+ `qc_beats_nonempty_groups`；下文变异表里 `NE.groupAllWith` 那一行现在由这两个测试抓到。`Spec.DataBoundary` 现有 10 个测试。

逐条论证：

- **校验**：`validateLevel` 只读关卡记录。`lookupLevel` 对通过校验的关卡原样返回，而现有全部关卡都通过（测试锁定）。`checkLevelDims` 的文字由同一段 `renderIssue` 给出，与原来逐字节相同（原有测试 `board_size_out_of_range_rejected` 照旧通过）。
- **`ArgP`**：每个解析器与它替换的模式逐支对应：
  - `exactArgs` 等价于固定长度的列表模式；
  - `prefixArgs` 等价于 `(x : _)`；
  - `p <|> pure d` 等价于「`[]` → d」那一支。
- **`beats`**：`NE.groupWith` 与原来的 `span` 递归是同一个算法；`toList` 之后逐项相同。
- **Generic**：只在测试里。

## 4. 类型能挡住什么，挡不住什么

| 错误 | 改动前 | 改动后 |
|------|--------|--------|
| 关卡表里皮带 / 传送门 / 飞碟 / 掉落口的格写到盘外 | 能编译，能开局，静默的错误行为 | 仍能编译；`lookupLevel` 取关时 error，列出全部问题（运行时边界，不是类型） |

| 处理 `beats` 的「空组」（或忘了处理） | 类型允许空组，用的一方要么写一支死代码，要么用 `head` 这类部分函数 | 类型错误：`Couldn't match expected type: GHC.Internal.Base.NonEmpty Effect with actual type: [a0]  In the pattern: []`；`NE.head` 是全函数 |

## 5. 取舍

- **行为不变**。验证：
  - 金标准、元素查询快照逐字节相同（没有重新生成）；
  - 原有 442 个测试全过，新增 9 个，共 451 个；
  - `stack build --test --ghc-options=-Werror`（库、桌面版、测试）0 警告。
- **没有动 `app/`、`web/hs` 与 `app/pure`**，也没有新增 `src` 模块，所以没有跑 `make check`（与前几项的约定一致：只有动了这三处才跑）。网页版只经 `src` 间接受影响，而 `src` 的行为由金标准与快照锁定。
- **`Validation` 手写，不用 `validation` / `either` 包**：二十几行，换来零依赖和一个能直接看懂的实例。没有 `Monad` 实例是刻意的（§1.1）。
- **`ArgP` 放在 `Match3.Element.Types`**（`Arg` 所在的模块），不另开模块：新模块要同步进网页版的 cabal 模块列表。
- **`ArgP` 只有 Applicative / Alternative**：放置参数的结构是固定的，用不到 Monad。`<|>` 只在一步之内回溯，不做完整回溯：现有的写法都只需要「这一个参数有没有」，完整回溯反而会让「精确匹配失败时为什么失败」更难推理。
- **`LevelIssue` 是数据，文字在 `renderIssue`**：测试比较的是结构化的问题列表（顺序、编号、格），不依赖中文措辞。只有 `BadDims` 的文字是兼容要求，单独锁死。
- **Generic 的类留在测试里**：src 里没有任何代码需要「列出全部构造器」。放进 src 就成了运行时 API，还要承诺它的稳定性。
- **源码扫描而不是 import**：`UI.CellTable` 依赖 SDL，`Match3Web.Api` 在网页版的包里，测试都 import 不到。扫描只认 `("名字", …)` 这一种表行形状、和 `tag "构造器名"`，表的写法变了，测试会失败而不是静默通过（找不到键就报缺失）。
- **测试里的旧副本**：`LegacyBoundary` 的 `case` 分支照抄 e548ace，只拆成按名字配对的表，不经过任何新 API（否则对照就成了自己比自己）。
