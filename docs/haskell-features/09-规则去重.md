## 1. 这些特性是什么

### 1.1 棱镜作参数（第 6 项的延续）

`Prism' Cell Int` = 「这一格是不是这种障碍；是的话焦点是层数」。同一个值既能拆（`preview` / `has`）、又能造（`review`）、又能改（`.~`，穿过 `cellAt p` 复合）。
把它当参数传进去，函数就对「哪种障碍」抽象了。参数要在函数体里以三种函子使用（`Const Any`、`Const (First Int)`、`Identity`），
所以参数类型必须是多态的 `Prism' …`（rank-2，模块开 `RankNTypes`）；只用一次的地方（`layersOf :: Getting (First Int) Cell Int -> …`、`mkLayers :: AReview Cell Int -> …`）传单态的就够。

### 1.2 遍历：一个定义同时是「读」和「写」

```haskell
cellColorT :: Traversal' Cell Color
cellColorT f cell = case cell of
  Gem c k i o   -> (\c' -> Gem c' k i o) <$> f c
  Countdown c n -> (`Countdown` n) <$> f c
  Flip c back   -> (`Flip` back) <$> f c
  _             -> pure cell
```

「哪些格有颜色」只写这一次：`cellColor = preview cellColorT`（读），`set cellColorT col`（写，原来的 `recolorCell`）。读和写不可能再不一致。

### 1.3 `mapAccumL`：状态穿过列表、每项吐一个输出

```haskell
mapAccumL :: Traversable t => (s -> a -> (s, b)) -> s -> t a -> (s, t b)
```

「依次执行一串规则，盘面从上一条传到下一条，顺便记下每条的效果」正是它：状态 = 盘面，输出 = 这条规则的记录。
手写 `foldl` 时，状态和输出挤在一个元组累积器里，输出还得前插再 `reverse` 才是正序；`mapAccumL` 把两者分开，输出天然按列表顺序。
第 2 项的 `randomBoardSized`（生成器穿过每一格）是同一个形状。

### 1.4 `Dual (Endo a)`：把「后面的覆盖前面的」写进类型

`Endo a` 是 `a -> a` 在复合下的幺半群：`Endo f <> Endo g = Endo (f . g)`——**先做右边**。
`Dual` 交换 `<>` 的左右：`Dual x <> Dual y = Dual (y <> x)`。所以

```haskell
Dual (Endo f) <> Dual (Endo g) = Dual (Endo (g . f))   -- 先 f 后 g
```

DerivingVia 让一个 newtype 直接借用另一个表示相同的类型的实例：

```haskell
newtype Cap = Cap (Caps -> Caps)
  deriving (Semigroup, Monoid) via Dual (Endo Caps)
```

`Cap` 与 `Dual (Endo Caps)` 都只是 `Caps -> Caps` 的包装（`Coercible`），实例零代价搬过来。于是 `mconcat [a, b, c]` = 先 a、再 b、再 c，**后面的覆盖前面的**。

### 1.5 按阶段的智能构造器

`EndRule` 的五个字段里，`erSeeds` 只在倒计时阶段之后被读（`Board.Cascade` 取引爆种子），`erHoles` 是给扩展元素声明「步末挖空」的槽，内置规则全是空。
智能构造器把「这个阶段有哪些槽」写进参数表：

```haskell
tickRule   :: Int -> EndRun -> (Board -> [Pos]) -> EndRule   -- 只有它收种子
spreadRule :: Int -> EndRun -> EndRule
moveRule   :: Int -> EndRun -> EndRule
```

## 2. 为什么用在这里

**占格障碍和叠层是同一个形状。** 第 6 项处理的是「宝石 → 叠层 → 某种叠层的层数」，这里是「格 → 某种障碍的层数」，少一层而已。
五个 `chipAdjacent*Except` 逐字相同——「与清除格正交相邻、不在 except 里的这种障碍各削一层；最后一层记进 dead」——
只差 `isX` / `xLayers` / `mkXLayers` 三个名字，外加**保险箱的末层不是留给清除管线、而是原地变成饼干**。前者是棱镜，后者是一个参数。

**改色是「读颜色」的另一半。** `Match3.Types.Cell.cellColor`（宝石 / 倒计时 / 双面块正面）和 `Match3.Obstacles.recolorCell`（同样三个分支改颜色）
是同一件事的 get 与 set，分在两个模块各写一遍。写成遍历后只有一份。

**步末折叠是同一个循环的三份拷贝。** `Board.Cascade.cascadeCountdownsM`（倒计时）、`Game.Trace.traceSpreadsWith`（蔓延）、`Game.EndPhase.runPhase`（会走的元素）
都是 `foldl one ([], b0) rules` + 前插 + `reverse`，只有上下文和「记录长什么样」不同；后两者连上下文之外都完全一样（蔓延就是 `runPhase PhaseSpread (EndCtx [] [] pushable)`），
只是 `EndPhase` import 了 `Trace`，不能反过来调用，于是抄了一份。`runEndRules` 放在两者都依赖的 `Element.Types`，`runPhaseSteps` 放在 `Trace`、`EndPhase` 直接用它。

**能力声明的顺序语义以前只在一行注释里。** `withCaps a = foldl (\c f -> f c) (capsOf a)` 的注释写着「后面的覆盖前面的」；
如果有人把它改成 `foldr`（或者 `foldl (flip (.)) id` 写反），类型不会报错——§3.5 的变异检查表明，**原有 429 个测试也不会**。
`Dual (Endo Caps)` 把这个语义变成了类型的一部分：`Cap` 的 `<>` 就是「先左后右」，想要相反的顺序就得换一个类型。

**没有动的地方（以及原因）：**

- **完整的阶段索引 `EndRule (p :: EndPhase)` + 类型族 + 注册表里的存在类型**：没有做，只做了智能构造器。原因：
  `erHoles` 不是倒计时专属——测试里的扩展元素「陷坑」（`Spec.Extension`）就在 `PhaseMove` 用它；元素查询快照（`test/golden/ElementQueries.hs`）
  对三个阶段的所有规则统一读 `erSeeds` / `erHoles` 并逐行比对；注册表按 `(阶段, erOrder)` 把规则排成一张异构表、`EndStage` 按 `Maybe EndPhase` 选行。
  做成 GADT 后这三处都要改成「按阶段分装 + 解包」，快照的生成代码也要跟着改（快照文本可以保持不变，但它就不再是「原样的旧代码跑出来的」）；
  换来的保证只是「非倒计时规则不能有种子」，而内置规则里这件事已经由 `tickRule` 的参数表和 `end_rule_smart_constructors` 测试锁住。收益配不上改动面。
- **`EndRule` 记录本身**：仍然导出全部字段，扩展元素（测试里的「陷坑」「跳跳虫」）和测试里的旧副本照旧直接构造。智能构造器是推荐写法，不是唯一写法。
- **`Board.Cascade` 里倒计时之后的「合并各规则的种子」**：`nub (concatMap (\r -> erSeeds r bTick) rules)` 已经是一行，没有复制，不动。
- **气球、果汁机、彩蛋、时间精灵**：它们没有层数（或者层数之外还有颜色），不是 `Prism' Cell Int` 的形状，削层 / 充能 / 开启逻辑各只有一份，保留原样；
  彩蛋、时间精灵（以及魔法帽、染色瓶）的相邻查询换成了 `adjacentWhere`，气球与果汁机的「同色相邻」查询要看清除格的颜色，形状不同，也保留原样。
- **`Match3.Grass` / `Match3.Types.Overlay`**：第 6 项已经做过。

## 3. 改动前后

### 3.1 占格障碍：五份 → 一份，种类是棱镜，末层的去向是参数

```haskell
-- 旧（Match3.Obstacles，石头；宝箱 / 蜂蜜 / 蛋糕各一份只换名字，保险箱末层写 mkCookie）
chipAdjacentStonesExcept b clearedGems except =
  foldl hitOne (b, []) [p | p <- stonesAdjacentTo b clearedGems, p `notElem` except]
  where
    hitOne (board, dead) p =
      case at board p of
        cell | isStone cell ->
          let n = stoneLayers cell
          in if n <= 1
               then (board, nub (p : dead))
               else (setAt board p (mkStoneLayers (n - 1)), dead)
        _ -> (board, dead)

-- 新
chipAdjacentLayeredExcept :: Prism' Cell Int -> Maybe Cell -> Board -> [Pos] -> [Pos] -> (Board, [Pos])
chipAdjacentLayeredExcept layer onLast b clearedGems except =
  foldl hitOne (b, []) [p | p <- adjacentWhere (has layer) b clearedGems, p `notElem` except]
  where
    hitOne (board, dead) p =
      case at board p ^? layer of
        Just n
          | n <= 1 -> (maybe board (setAt board p) onLast, nub (p : dead))
          | otherwise -> (board & cellAt p . layer .~ n - 1, dead)
        Nothing -> (board, dead)

chipAdjacentStonesExcept = chipAdjacentLayeredExcept _Stone Nothing
chipAdjacentSafesExcept  = chipAdjacentLayeredExcept _Safe (Just mkCookie)
```

`Match3.Types.Body` 同理：

```haskell
-- 旧（×5）
mkStoneLayers n = Stone (max 1 n)
stoneLayers (Stone n) = n
stoneLayers _ = 0
isStone (Stone _) = True
isStone _ = False
-- 新
mkStoneLayers = mkLayers _Stone        -- mkLayers layer n = review layer (max 1 n)
stoneLayers = layersOf _Stone          -- layersOf layer = fromMaybe 0 . preview layer
isStone = has _Stone
```

魔法帽 / 染色瓶的改色：

```haskell
-- 旧
| Just c1 <- cellColor (at board p1), Just c2 <- cellColor (at board p2) ->
    let b1 = setAt board p1 (recolorCell (at board p1) c2)
    in setAt b1 p2 (recolorCell (at board p2) c1)
-- 新
| Just c1 <- board ^? cellAt p1 . cellColorT, Just c2 <- board ^? cellAt p2 . cellColorT ->
    board & cellAt p1 . cellColorT .~ c2 & cellAt p2 . cellColorT .~ c1
```

### 3.2 步末折叠：`foldl` + `reverse` → `mapAccumL`

```haskell
-- 旧（Game.Trace.traceSpreadsWith；Game.EndPhase.runPhase 与 Board.Cascade.cascadeCountdownsM 各一份同样的）
traceSpreadsWith reg k b0 =
  let (stepsRev, b1) = foldl one ([], b0) (endRules reg PhaseSpread)
  in (reverse stepsRev, b1)
  where
    one (accRev, before) rule =
      let (eff, after) = erRun rule (EndCtx [] [] (pushableWith reg)) before
      in ([EndStep k before after e | Just e <- [eff]] ++ accRev, after)

-- 新（Element.Types）
runEndRules :: EndCtx -> [EndRule] -> Board -> ([(Board, Board, EndEffect)], Board)
runEndRules ctx rules b0 =
  let (b1, recs) = mapAccumL one b0 rules
  in (catMaybes recs, b1)
  where
    one before rule =
      let (eff, after) = erRun rule ctx before
      in (after, fmap (\e -> (before, after, e)) eff)

-- 新（Game.Trace）：蔓延与 EndPhase.runPhase 共用
runPhaseSteps reg ph ctx k b0 =
  let (recs, b1) = runEndRules ctx (endRules reg ph) b0
  in ([EndStep k before after e | (before, after, e) <- recs], b1)
traceSpreadsWith reg = runPhaseSteps reg PhaseSpread (EndCtx [] [] (pushableWith reg))
```

邻格波及的四元组累积器拆成「状态」与「输出」：

```haskell
-- 旧
let (b', deadRev, sitsRev, _) = foldl one (b0, [], [], nub protect0) (regAdjacent reg)
in (b', concat (reverse deadRev), concat (reverse sitsRev))
-- 新
let ((b', _), outs) = mapAccumL one (b0, nub protect0) (regAdjacent reg)
in (b', concatMap fst outs, concatMap snd outs)
```

### 3.3 能力声明：`Dual (Endo Caps)` 与字段透镜

```haskell
-- 旧
type Cap = Caps -> Caps
withCaps a = foldl (\c f -> f c) (capsOf a)
withMatch f c = c {capMatch = f (capMatch c)}
swappable = withMatch (\m -> m {mcBlocksSwap = False})
counts k  = withCount (\x -> x {ccCounter = Just k})

-- 新
newtype Cap = Cap (Caps -> Caps)
  deriving (Semigroup, Monoid) via Dual (Endo Caps)
withCaps a cs = applyCap (mconcat cs) (capsOf a)
withMatch = Cap . over matchL
swappable = setCap (matchL . mcBlocksSwapL) False
counts k  = setCap (countL . ccCounterL) (Just k)
```

`blocker [hit …, onAdjacent …, counts …]` 这类调用一个字没改：列表元素的类型从函数换成了 newtype，写法相同。

### 3.5 为什么行为不变，以及哪些测试守着

> **后来的变化**：死代码清理删除了 `LegacyObstacles` / `LegacyRules`（以及第 9 刀的 `LegacyElement`，见[旧副本对照的去留](../testing.md#旧副本对照的去留)）。`qc_dedup_caps_same_as_legacy` → `dedup_caps_examples_pinned`（7 个 `capsSig` 例子，第 4 个就是下文 `via Endo Caps` 的反例）+ `qc_caps_monoid_laws`，`qc_dedup_obstacles_same_as_legacy` → `dedup_obstacle_orders_pinned`（蜂蜜 / 宝箱 / 保险箱的相邻格与末层位置，含 except），`qc_dedup_rule_folds_same_as_legacy` 只留 `qc_run_end_rules_is_fold`，`qc_dedup_body_readers_same_as_legacy` 删除（棱镜律与快照重复）。复测下文前两个变异：`dead ++ [p]` → `dedup_obstacle_orders_pinned`、`effects_entries_pinned`、金标准、`ec_play_matches_stage1_snapshot` 失败；`via Endo Caps` → `dedup_caps_examples_pinned`、`qc_caps_monoid_laws` 失败。`Spec.RulesDedup` 仍是 6 个测试。

逐条论证（每条都有对应的对照性质，见下表）：

- **列表顺序**：`chipAdjacentLayeredExcept` 的目标列表、`foldl` 方向、`nub (p : dead)` 的前插全部原样保留（末层位置是**逆序**的，游戏的清除格顺序依赖它）；
  `adjacentWhere ok` 与九份旧列表推导逐字相同，只是把谓词提成参数；`has _Stone = isStone`。
- **写回的值**：旧代码在 `n > 1` 时写 `mkStoneLayers (n - 1) = Stone (max 1 (n - 1)) = Stone (n - 1)`，新代码写 `review _Stone (n - 1) = Stone (n - 1)`，相同；
  棱镜的 `review` 是原样构造器（守棱镜定律），「至少 1 层」只在 `mkXLayers` 里。
- **改色**：`cellColorT` 的三个分支与 `recolorCell`、`cellColor` 的分支一一对应；魔法帽两格不同（`nub (sort …)` 之后），所以先写 p1 再在新盘面上读写 p2 与旧代码读原盘面相同。
- **折叠**：「前插再整体 `reverse`」= 按规则顺序；`mapAccumL` 的输出本来就是按规则顺序；`concat (reverse deadRev)` = `concatMap fst outs`。
- **能力声明**：`applyCap (mconcat [c1 … cn]) = cn . … . c1`，与 `foldl (\c f -> f c)` 相同。

## 5. 取舍

- **行为不变**。验证：金标准 3373 行、元素查询快照逐字节相同（没有重新生成）；原有 429 个测试全过，新增 6 个（共 435 个）；`stack build --ghc-options=-Werror` 0 警告。
- **没有动 `web/hs` 与 `app/pure`**，也没有新增 `src` 模块（`web/match3-web.cabal` 不变）。核心模块的源码变了，网页版下次构建 `match3-web.wasm` 时会编进去；
  本分支没有提交重建的 `web/dist`（与第 1–6 项一样，wasm 产物另起提交）。新用到的扩展 `DerivingVia`（`Element.Caps`）、`RankNTypes`（`Types.Cell`、`Obstacles`、`Element.Caps`）都按模块写了 pragma，
  网页版的 Haskell2010 构建不需要改配置。
- **行数**：`Match3.Obstacles` 499 → 413、`Match3.Types.Body` 259 → 265（逐个 case 变成一行，但多了两个辅助与说明）、`Match3.Element.Caps` 212 → 345。
  后者**变长了**：27 个嵌套记录更新换成了 28 个透镜定义（每个一行）加导出列表，写入器本身变成一行一个。收益不在行数，而在
  「顺序语义进了类型」「写入器是可复合的透镜（扩展元素可以 `setCap (hitL . hcBlastL) …`）」。透镜是手写的（同第 6 项，没有 Template Haskell）。
- **棱镜的 `review` 不夹层数**：`review _Stone 0 == Stone 0`。这是为了守棱镜定律（`preview p (review p n) == Just n` 对所有 `n` 成立）；
  「至少 1 层」是关卡放置的约定，留在 `mkStoneLayers` 等里。削层只在 `n > 1` 时写 `n - 1`，不会写出 0 层。
- **`runEndRules` 放在 `Element.Types`**：它是 `EndRule` 的执行语义，`Board.Cascade` 与 `Game.Trace` 都依赖这个模块；放进注册表模块也可以，但它用不到注册表。
- **测试里的旧副本**：`LegacyObstacles` 把旧 `Body` / `Cell` 读数也一起复制，旧函数不经过任何新写法（否则「对照」就成了自己比自己）；
  `LegacyRules` 的 `runAdjacentWith` 经导出的 `adjacentRules` 取规则表（与旧代码的 `regAdjacent` 是同一个字段）。
